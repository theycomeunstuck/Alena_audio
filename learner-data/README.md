# learner-data

`learner-data/` — демонстрационный набор из 12 профилей учеников для
персонализации будущего ИИ-репетитора. Это **не** векторная база учебных
материалов и не production-хранилище персональных данных.

Каждый файл `learners/<learner_id>.json` содержит две разные вещи:

1. **Полную карточку**: история, интересы, ошибки, журнал, баллы и другие
   наблюдения. Она нужна педагогу, аналитике и benchmark-проверкам.
2. **`rag_context`**: короткая вручную выбранная выжимка. Только она уходит в
   ИИ-репетитор при обычном запросе.

`legal_name` — необязательное ФИО для закрытого интерфейса: `first_name`,
`last_name`, `patronymic`. У отчества допустимы пустая строка или `"-"`.
Эти данные не попадают в `rag_context`, логи RAG или prompt модели.

Такое разделение намеренное: подробности о ребёнке не должны автоматически
попадать в каждый запрос к модели.

## Что лежит в папке

```
learner-data/
├── README.md
├── RAG_HANDOFF.md                 # короткий контракт для команды RAG

│   ├── learner_card.schema.json   # схема карточки, версия 2
│   └── skills_catalog.schema.json
├── catalog/math_g3_g4.json        # общий каталог тем математики 3–4 класса
├── learners/
│   ├── _TEMPLATE.json
│   └── <learner_id>.json          # 12 синтетических профилей
├── benchmarks/
│   └── rag_behavior_cases.json    # 12 сценариев проверки будущего RAG
└── tools/
    ├── validate.py
    ├── build_context.py
    ├── learner_common.py
    └── selftest.py
```

## Что получает RAG

```bash
python learner-data/tools/build_context.py volk-08
```

Команда печатает компактный блок из:

- имени для обращения, класса и языка;
- одной текущей учебной цели;
- максимум трёх текущих тем;
- максимум трёх главных трудностей;
- максимум трёх способов помочь;
- списка «чего избегать»;
- одной свежей заметки о прогрессе.

В этот вывод **не** попадают `interests`, подробные `knowledge`,
`error_patterns`, `mvp.journal`, `mvp.points_ledger` и `learner_model`.
Полную карточку можно посмотреть только в диагностическом/педагогическом
инструменте:

```bash
python learner-data/tools/build_context.py volk-08 --format json
```

Этот JSON нельзя отправлять в RAG как есть.

## Как заполнять `rag_context`

`rag_context` — не автоматическая копия всей карточки. Педагог сам выбирает
самое актуальное для следующего объяснения:

```json
"rag_context": {
  "current_goal": {
    "topic_id": "math.g4.numbers.division_by_1_2_digit",
    "goal": "закрепить деление столбиком",
    "updated_at": "2026-07-12"
  },
  "current_topics": ["math.g4.numbers.division_by_1_2_digit"],
  "priority_difficulties": [
    {
      "topic_id": "math.g4.numbers.division_by_1_2_digit",
      "description": "теряет ноль в частном"
    }
  ],
  "effective_strategies": ["сначала проговорить план решения"],
  "avoid": ["не давать длинную цепочку действий без проверки"],
  "recent_progress": {
    "date": "2026-07-12",
    "note": "Деление остаётся главным приоритетом."
  }
}
```

Ограничения в три элемента и 280 символов на текст — специально, чтобы
контекст оставался коротким и понятным модели.

## Полный benchmark-профиль

`learners/volk-08.json` содержит дополнительный `learner_model`: карту
компетенций, ЗБР, наблюдения о вовлечённости, работе с ИИ, проектах и
геймификации. Он соответствует более широкому концепту Learner Model и нужен
как богатый тестовый случай. `build_context.py` его не читает для текстового
RAG-вывода.

## Важно для будущей базы учебных материалов

В каждом фрагменте учебника, упражнении или задании будущего RAG должны быть
те же `topic_id`, что и здесь, а также класс и сложность. Например:

```json
{
  "topic_id": "math.g4.numbers.division_by_1_2_digit",
  "grade": "4",
  "difficulty": "easy"
}
```

Тогда система сможет не только изменить стиль объяснения, но и найти материал
по нужной теме.

## Проверки

```bash
python learner-data/tools/validate.py --strict
python learner-data/tools/selftest.py
```

Самопроверка включает валидность 12 карточек, изоляцию профилей, запрет утечки
журнала/баллов/полной модели в RAG-контекст и 12 сценариев будущего RAG.

## Данные детей

В репозитории только вымышленные примеры. Реальные имена, контакты, даты
рождения, диагнозы, аудио и расшифровки занятий здесь хранить нельзя. Для
реального запуска нужен отдельный закрытый сервис с доступами, а не коммиты в
этот репозиторий.
