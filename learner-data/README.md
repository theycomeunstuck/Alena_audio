# learner-data

## 1. Что это

`learner-data/` — пакет профилей учеников для персонализации ИИ-репетитора.
Один файл = один ребёнок. Данные ведутся вручную репетиторами (без
программирования) в обычных JSON-файлах.

Эти профили читает RAG-система коллеги, чтобы ИИ-репетитор учитывал сильные
и слабые стороны, интересы и историю ошибок конкретного ребёнка при
объяснении материала.

## 2. Структура папки

```
learner-data/
├── README.md                        # этот файл — правила ведения пакета
├── schemas/
│   ├── learner_card.schema.json     # контракт карточки ученика (для разработчиков)
│   └── skills_catalog.schema.json   # контракт каталога тем (для разработчиков)
├── catalog/
│   └── math_g3_g4.json              # каталог тем по математике 3–4 класс (появится позже)
├── learners/
│   ├── _TEMPLATE.json               # шаблон для создания новой карточки ученика
│   └── <learner_id>.json            # карточки учеников, по одному файлу на ребёнка
└── tools/
    ├── validate.py                  # проверка всех карточек на соответствие схемам
    └── build_context.py             # сборка контекста для ИИ-репетитора по одному ученику
```

Папки `catalog/`, `learners/` и `tools/` появятся в следующих коммитах —
пока в репозитории есть только `README.md` и `schemas/`.

## 3. Как завести ребёнка

1. Скопировать `learners/_TEMPLATE.json` в `learners/<learner_id>.json`.
2. Заполнить карточку по правилам из раздела 4.

Правила для `learner_id`:

- только маленькие латинские буквы, цифры и дефис, например `sova-01`;
- имя файла должно совпадать с `learner_id` (без `.json`);
- после создания карточки `learner_id` **не переименовывать** — от него
  зависят ссылки в RAG-системе.

## 4. Правила заполнения

- **Только псевдонимы.** Запрещено указывать реальные имена, контакты
  (телефон, email, адрес), даты рождения, диагнозы, а также прикреплять
  аудиозаписи или транскрипты занятий.
- **Даты** — строго в формате `YYYY-MM-DD`, например `2026-07-13`.
- **Статусы освоения навыков** — ровно четыре значения, числовых оценок
  (баллов, процентов, «5 из 10» и т.п.) не существует:
  - `not_started` — не начинали;
  - `learning` — изучает;
  - `confident` — уверенно владеет;
  - `needs_support` — нужна поддержка.
- **`topic_id`** берётся только из каталога `catalog/math_g3_g4.json` —
  всегда копировать оттуда, никогда не печатать вручную (легко ошибиться).
- **`points_ledger`** (журнал баллов) — только добавление новых строк в
  конец файла (append-only). Исправлять уже записанные строки **нельзя** —
  если баллы начислены ошибочно, нужно добавить новую корректирующую
  запись. Итоговый баланс баллов в файле **не хранится** — он всегда
  вычисляется как сумма по журналу.
- **Кодировка** — все файлы в UTF-8. Редактировать в VS Code, Notepad++
  или подобном текстовом редакторе. **Никогда не открывать и не сохранять
  в Word** — он ломает кодировку и структуру JSON.

## 5. Рабочий цикл

```
git pull
# ... правка карточки(ек) ...
python learner-data/tools/validate.py
git push
```

Один файл на ребёнка — это специально, чтобы у разных репетиторов, правящих
разные карточки одновременно, не возникало конфликтов при `git pull`/`git push`.

## 6. Инструменты

Появятся в этом же пакете (в одном из следующих коммитов):

- `tools/validate.py` — проверяет все карточки в `learners/` на соответствие
  схемам из `schemas/`; запускать перед каждым `git push`.
- `tools/build_context.py <learner_id>` — собирает контекст по конкретному
  ученику для передачи ИИ-репетитору.
