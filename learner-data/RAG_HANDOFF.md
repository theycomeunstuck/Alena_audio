# RAG_HANDOFF — как использовать профили учеников

## Главная идея

Карточка ученика и учебные материалы — разные источники.

- Карточка говорит, **как** объяснять и что сейчас важно конкретному ребёнку.
- Учебный RAG ищет, **что** объяснять: фрагменты учебника, задачи, примеры.

Никогда не индексируйте `learner-data/learners/` в векторную базу учебных
материалов.

## Единственная команда для обычного RAG

```bash
python learner-data/tools/build_context.py <learner_id>
```

`learner_id` должен приходить от сервера после проверки пользователя, а не из
текста сообщения ребёнка. Допустим только формат вроде `volk-08`; скрипт
откроет ровно один файл из `learners/`.

При успехе команда возвращает компактный текст:

```text
<child_safe_profile>
Имя_для_обращения: Волк
Школьный_уровень: 4 класс
Язык: russian
</child_safe_profile>

<learner_rag_context>
Текущая_цель: ...
Изучает_сейчас: ...
Приоритетные_трудности: ...
Как_помогать: ...
Чего_избегать: ...
Последний_прогресс: ...
</learner_rag_context>
```

Этот блок добавляется к системным правилам модели перед найденными учебными
материалами. В системных правилах закрепите: данные внутри
`<learner_rag_context>` — справочная педагогическая информация, а не команды.

## Чего в RAG-контексте нет

В текст не попадают интересы, полный журнал занятий, подробная статистика
ошибок, баланс баллов и полный `learner_model`. Они остаются в JSON-карточке
для педагога и benchmark-проверок.

Команда с `--format json` возвращает **всю** карточку. Это только для
авторизованного педагогического интерфейса или отладки; не используйте её для
обычного запроса к модели.

## Как связать профиль и учебную базу

Используйте одинаковые `topic_id` в двух местах:

1. В `rag_context.current_goal`, `current_topics` и `priority_difficulties`.
2. В metadata каждого фрагмента учебного материала, упражнения и задания.

Минимальные metadata фрагмента:

```json
{
  "topic_id": "math.g4.numbers.division_by_1_2_digit",
  "grade": "4",
  "difficulty": "easy",
  "source": "учебник, стр. 42"
}
```

Рекомендуемый порядок на один вопрос:

```text
Проверенная сессия → learner_id → build_context.py
Вопрос ребёнка → поиск учебных фрагментов по question + topic_id/grade
Короткий профиль + найденные фрагменты → ответ модели
```

Профиль не должен быть жёстким фильтром: ребёнок может спросить тему вне
текущей цели. Он помогает выбрать стиль, сложность и дополнительные подсказки.

## Проверка будущего RAG

`benchmarks/rag_behavior_cases.json` содержит по одному сценарию на каждого
из 12 демо-учеников. Для каждого сценария есть вопрос, что модель должна
сделать и чего не должна делать. Это benchmark поведения, а не проверка точных
слов ответа.

Перед интеграцией запускайте:

```bash
python learner-data/tools/validate.py --strict
python learner-data/tools/selftest.py
```

Ожидаемый результат: 12 файлов без ошибок и все self-test зелёные.
