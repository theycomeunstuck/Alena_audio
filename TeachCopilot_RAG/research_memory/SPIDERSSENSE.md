# Spiderssense: изолированный клиент исследования

Адаптер не делает сетевых запросов при создании и `preflight()`. Реальные генерации до предоставления ключа и команды на запуск не выполнялись. Совместимость выбранной модели с конкретным запросом предстоит подтвердить коротким smoke-тестом.

## Интерфейс

`SpiderssenseClient` из `research_memory.spiderssense` реализует `complete(messages, purpose, response_schema=None) -> Completion` из `clients.py`. Получение ответа не подтверждает соответствие JSON Schema – смысловой и структурный контроль ответа выполняет вызывающий код.

Обязательные параметры конструктора:

- `model` – точный ID из текущего каталога провайдера.
- `input_usd_per_million`, `output_usd_per_million` – явно проверенные тарифы выбранной модели в USD за миллион токенов.
- `pricing_verified=True`, `pricing_source` – подтверждение проверки тарифов вызывающим кодом и публичная ссылка на `https://spiderssense.com/...` без параметров и учётных данных. Сам флаг не проверяет цены в интернете.

Основные необязательные параметры:

- `ledger_path` – постоянный SQLite-журнал; по умолчанию `.local/research_memory/spiderssense_budget.sqlite3` относительно текущей рабочей папки.
- `max_cost_usd="4"`, `max_calls=32` – общий предел этого журнала, включая уже завершённые и неопределённые вызовы.
- `max_output_tokens=1536`, `token_field="max_completion_tokens"` – явное имя поля ограничения вывода. Допускается также `max_tokens`; автоматической замены после ошибки нет. Для reasoning-модели нужен лимит, учитывающий также внутренние токены рассуждения; совместимость провайдера необходимо проверить.
- `reasoning_effort=None` – при задании отправляется как есть, например `"medium"`; допустимость значения зависит от модели. `temperature` не отправляется.
- `timeout=180` – ожидание ответа в секундах.
- `key_file` – локальный файл ключа; по умолчанию `.local/research_memory/spiderssense.key`.
- `use_json_schema=False` – по умолчанию схема добавляется в текст инструкции. При явном `True` отправляется `response_format.type=json_schema` со `strict=True`; поддержку выбранной моделью предварительно проверяют.

Endpoint фиксирован: `https://spiderssense.com/v1/chat/completions`. Прокси из окружения и редиректы отключены. Вызов не потоковый, тело ответа ограничено 8 MiB, сетевых повторов нет. Завершение принимается только с `finish_reason="stop"`; частичный текст и известные затраты сохраняются в `CompletionValidationError`.

Ключ читается только внутри `complete()`: сначала из `SPIDERSSENSE_API_KEY`, иначе из указанного файла. Ключ не нужно присылать в чат, помещать в JSON-конфигурацию, аргументы командной строки или коммитить. Адаптер не выводит содержимое серверных ошибок; обнаруженное полное повторение ключа в тексте ответа заменяется маркером и считается ошибкой. `preflight()` сообщает только наличие переменной или файла, модель, тарифы, доступный бюджет и число вызовов.

## Как ограничиваются расходы

Перед сетью SQLite-транзакция с `BEGIN IMMEDIATE` атомарно проверяет лимиты и сохраняет резерв. Он рассчитывается по числу UTF-8-байтов сериализованного запроса плюс 4096 входных токенов запаса, максимальному выводу, множителю входной цены 1.25 и общему запасу 1.10. Множители можно увеличить, уменьшить ниже 1.25 и 1.00 нельзя.

Это консервативная клиентская модель стоимости. Она не является банковской гарантией для стороннего сервиса: скрытые обёртки, изменение тарифов, особые типы токенов и фактическая тарификация находятся на стороне провайдера. Используются только текстовые запросы без инструментов и медиа.

При сетевой ошибке, неизвестном исходе, недоступном или неполном `usage` весь резерв остаётся занятым. При полном корректном `usage` журнал сохраняет максимум из расчёта по известным тарифам с входным множителем и числового `usage.cost`, если поле есть. Универсальная валюта `usage.cost` для текстовых ответов публично описана неполно – значение рассматривается как USD только для консервативного сопоставления, а исходная величина сохраняется отдельно. Отсутствие `usage.cost` не мешает расчёту по полным счётчикам токенов. Некорректное присутствующее `usage.cost` не позволяет освободить резерв.

Если фактический счётчик токенов или стоимость превышают резервные предположения, дальнейшие вызовы этого журнала блокируются. После сбоя перезапуск продолжает учитывать прежние резервы и расходы. Модель, цены, предел, параметры вывода и reasoning фиксируются fingerprint; изменить их при возобновлении нельзя. Все фоновые процессы одного пакета должны использовать один и тот же журнал. Создание нового журнала означает новый независимый бюджет, поэтому его нельзя использовать как автоматический обход предела $4. В текущей конфигурации один журнал привязан к одной модели; общий бюджет нескольких различных моделей потребует дополнительного координирующего слоя.

Низкоуровневый клиент не проверяет происхождение учебных данных. Разрешение только синтетических примеров и удаление идентификаторов для будущих реальных данных обеспечивает вызывающий исследовательский процесс.

## Что подтверждено публичными источниками

Проверка выполнена 16 октября 2026 года, без ключа и без генеративных вызовов.

- [Документация Spiderssense](https://spiderssense.com/docs) описывает базовый OpenAI-совместимый URL, Bearer-аутентификацию и chat completions. Автоматическое открытие HTML иногда попадает в цепочку редиректов; поисковый индекс возвращает текст этой официальной страницы.
- [Публичный каталог `/v1/models`](https://spiderssense.com/v1/models) доступен без авторизации. Текущий формат содержит `id`, `context_length`, `supported_parameters`, `top_provider.max_completion_tokens`, `pricing.prompt` и `pricing.completion`. Тарифы представлены десятичными строками за токен; для передачи в адаптер их умножают на 1 000 000. Каталог может меняться, поэтому для реального пакета сохраняют датированный снимок выбранной строки.
- [Официальный сайт](https://spiderssense.com/) и документация связывают баланс с USD. В документации есть пример `usage.cost` для изображения, но явной общей спецификации единиц, округления и включённых компонентов для текстовых chat completions не найдено.
- Документация описывает бесплатный `POST /v1/messages/count_tokens` с действительным ключом. Этот адаптер его не вызывает; клиентский резерв не зависит от дополнительного сетевого запроса.

Наличие параметра в каталоге не доказывает его корректное исполнение шлюзом. До smoke-теста не заявляется проверенная поддержка JSON Schema, reasoning effort или конкретного поля максимума токенов.

Проверки адаптера выполняются без сети и с подставным ключом: `python -m unittest research_memory.tests.test_spiderssense -v`.
