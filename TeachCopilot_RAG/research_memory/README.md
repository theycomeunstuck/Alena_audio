# Пилот памяти образовательного ассистента

Обновление 16 октября: реализован [конечный фоновый процесс](BACKGROUND.md) с возобновлением, калибровкой судьи и адаптером Spiderssense. Для расширенных dev-прогонов используется отдельный [набор v2](data/v2/README.md); пять исходных историй ниже сохранены без изменений.

Завершена [локальная версия ссылок и условий помощи](../../../nirs/21_canonical_sources_dev_results.md), `pilot-0.2-canonical-sources`: 59 из 64 ответов прошли техническую проверку, пять отклонены. Целевой аудит Sol 6.1 max выявил сохраняющиеся смысловые ошибки; формальные метки API-судьи для новых ответов не получались. 140 программных проверок пройдены, публичных API-вызовов не было. Бюджет 4000 символов относится только к выбранной памяти, размер схемы с допустимыми ID записывается отдельно как `response_schema_chars`.

Отдельный исследовательский стенд на Python 3.12 со стандартной библиотекой. Он не изменяет рабочую БД, карточки учеников, API или интерфейс TeachCopilot. Пять входных историй полностью вымышлены и предназначены для разработки. Их содержательная проверка человеком ещё не выполнена.

Для просмотра данных откройте [лист проверки пяти историй](teacher_review.md). Замечания можно прислать в чат по ID истории, без редактирования JSON. По последнему запросу пользователя dev-этап продолжается с машинной содержательной проверкой; просмотр человеком его не блокирует.

[Отчёт первого реального локального прогона](pilot_report.md) содержит фактические вызовы, затраты и найденную смысловую ошибку. Прохождение формата не означает правильность учебного вывода.

## Что реализуется

Четыре условия при одинаковом общем профиле и запросе:

- `profile_only` – только текущий общий профиль.
- `tail` – последние фрагменты истории с датами, авторами и источниками.
- `summary` – последовательно обновляемое свободное резюме.
- `structured` – наблюдения с цитатами, условиями помощи и указанием исправлений.

Память строится только по завершённым занятиям. Будущие вопросы и `gold.dev.jsonl` в построение памяти не передаются. Эталон хранится отдельно как предварительная рубрика для человека; стенд не выставляет себе оценку по совпадению слов или метки действия.

Бюджет выбранной памяти – 4000 **символов**, включая даты, ссылки и JSON. Это не равный лимит токенов. Журнал сохраняет фактические токены, когда их возвращает модель. Бюджет полного запроса и поведение модели нужно проверять отдельно; пилотные истории короткие и не демонстрируют преимущество на длинных историях.

`fixture` выдаёт заранее заданные технические ответы для проверки передачи данных. Он не анализирует учебную историю и не оценивает качество памяти. Такие результаты отмечаются `contract_only`, `scientific_result=false`.

`ollama` вызывает уже доступную локальную модель. Даже реальные ответы модели на этих примерах остаются `pilot_unreviewed`, `scientific_result=false`, пока нет независимой проверки и зафиксированного итогового протокола.

## Запуск

Откройте PowerShell в `C:/Users/name/PycharmProjects/misc/teachCopilot/Alena_audio/TeachCopilot_RAG`.

Проверка входных файлов:

```powershell
python -m research_memory validate
```

Проверка программных контрактов:

```powershell
python -m unittest discover -s research_memory/tests -t . -v
```

Технический прогон всех пяти историй без модели:

```powershell
python -m research_memory run --backend fixture --output .local/research_memory/contract-001
```

Небольшой реальный локальный прогон одной истории:

```powershell
python -m research_memory run --backend ollama --history-id h01 --max-calls 20 --output .local/research_memory/local-h01-001
```

Модель по умолчанию – `gemma4:12b`, адрес – `http://127.0.0.1:11435`. Изменить можно через `--model` и `--base-url`. Параметры находятся в [config.json](config.json). Клиент принимает только локальный HTTP endpoint, отключает прокси и редиректы; этот модуль пока не является адаптером публичного API.

Новая папка результатов создаётся с запретом перезаписи. Для следующего запуска задайте другое имя. `--max-calls` ограничивает реальные попытки вызова клиента; ошибки и исчерпание лимита остаются в результатах, а не исчезают из числа случаев.

Экспорт ответов для ручной оценки:

```powershell
python -m research_memory export-review --run-dir .local/research_memory/local-h01-001 --output .local/research_memory/review-h01-001
```

В `review.jsonl` ответы перемешаны, названия способов не показываются, оценочные поля пустые. `mapping.private.json` содержит соответствие кодов ответов способам; его не показывают проверяющему до оценки. Сам формат объяснения может косвенно раскрывать способ, поэтому это ограниченное сокрытие названия метода.

## Что считается проверкой

Код проверяет формат, существование источника, принадлежность теме, наличие новой реплики в наблюдении и буквальное совпадение цитаты. Это не проверка истинности смысла и не доказательство педагогической пригодности действия.

Человек проверяет как минимум фактическое основание, помощь/самостоятельность, исправление старой записи, обоснованность следующего шага и необходимость уточнения. Все первые пять историй – `dev`; на них можно исправлять протокол, но нельзя получать независимую итоговую оценку качества.

Дальнейший согласованный объём НИРС: 24 истории, 8 для настройки и 16 для теста; по два запроса на тестовую историю; четыре условия – 128 ответов основного прохода. Этот итоговый набор пока не подготовлен и не проверен.
