# Исследовательский стенд персональной памяти

Исследовательский стенд работает отдельно от прежних прогонов и предназначен для синтетических историй. Мост Graphiti + LangGraph также подключён к приложению как отключённая по умолчанию экспериментальная возможность для преподавательского шага и чата. Это кандидат для пробы, а не победитель сравнения. Смысловая точность воспоминаний и ссылок требует независимой оценки и проверки преподавателем.

## Состав

- `archive.py` – оригиналы занятий, реплики, поисковые фрагменты и журнал индексации в схеме `nirs_personal_memory` PostgreSQL. Все операции ограничены запуском и ребёнком.
- `backends.py` – адаптеры Graphiti и Mem0. Индексы не заменяют оригинал. Mem0 получает отдельную внутреннюю сессию для каждого фрагмента занятия, чтобы не приписывать текущему источнику сведения из предыдущих фрагментов. Graphiti предварительно отбирает кандидаты на небольших фрагментах: этот отбор может пропустить важную запись, хотя оригинал остаётся в архивном поиске.
- `workflow.py` – LangGraph для поиска, подгрузки исходных реплик и выбора блока памяти. Факты без разрешённого источника исключаются из запроса модели.
- `experiment.py` – девять условий, два бюджета, журнал вызовов и отдельные строки для технических отказов. Генератор не открывает файлы `gold`.
- `comparison.py` – автономный HTML для просмотра ответов, памяти, графа и истории. Технический статус не является оценкой правильности.
- `prepare_data.py` и `data/` – шесть вымышленных историй, вопросы и отдельные ориентиры оценки. Два удлинённых случая содержат механические упражнения и предназначены для нагрузки, а не для имитации живого разговора.

Кандидат воспоминания может быть ошибочным даже при существующей ссылке. Проверка кода устанавливает принадлежность ссылки видимым репликам, но не доказывает смысловую поддержку каждого утверждения. Граф может опираться на несколько эпизодов; если происхождение не разрешено целиком, факт не передаётся генератору. Для длинного занятия в ответ подаются найденные исходные фрагменты; производные факты не добавляются к отдельному фрагменту как подтверждённые.

## Окружение

Для текущего запуска создано отдельное окружение `.local/personal-memory-venv`, зависимости зафиксированы в `requirements.lock.txt`. Нужны локальные Ollama с `gemma4:12b` и `bge-m3`, PostgreSQL с pgvector и Neo4j Community. Текущий исследовательский сервер Neo4j слушает только `127.0.0.1:17687`; пароль хранится в локальной папке среды и не записывается в отчёты. Telemetry Graphiti и Mem0 отключена. Доступ к действующему PostgreSQL берётся из `.local.env` приложения, а не из отчётов.

Из папки `Alena_audio/TeachCopilot_RAG`:

```powershell
..\..\.local\personal-memory-venv\Scripts\python.exe -m unittest research_memory.personal_memory_lab.tests.test_protocol -v
..\..\.local\personal-memory-venv\Scripts\python.exe -m research_memory.personal_memory_lab.verify_storage
```

Технический запуск одного нового сценария и одного вопроса в двух бюджетах:

```powershell
..\..\.local\personal-memory-venv\Scripts\python.exe -m research_memory.personal_memory_lab.experiment --history-id pm-h01 --question-limit 1 --budget both --output ../../.local/personal-memory/pilot-new
```

Используйте новое имя папки: существующий результат не перезаписывается. По умолчанию используются dev-истории. Отложенную часть передают явно через `--histories` и `--requests` после завершения настройки протокола. Допустимые окна модели – 16 384 и 32 768 токенов; расширенный бюджет выбранной памяти оставляет 4096 токенов для остального запроса и ответа. До каждого близкого к пределу запроса выполняется осторожная проверка с резервом под шаблон сообщений.

В `manifest.json` фиксируются модель, отпечатки кода и данных, выбранные условия и статус. `calls.jsonl`, `legacy_calls.jsonl`, `ingestion.jsonl` и `results.jsonl` записываются по мере работы. Если содержимое кода изменилось во время запуска, результат помечается отдельно. Технические отказы остаются строками результатов, а не удаляются.

Сформировать HTML после запуска:

```powershell
..\..\.local\personal-memory-venv\Scripts\python.exe -m research_memory.personal_memory_lab.comparison --run-dir ../../.local/personal-memory/pilot-new --histories research_memory/personal_memory_lab/data/histories.dev.jsonl --output ../../.local/personal-memory/pilot-new.html
```

## Восстановление

Внешний индекс и PostgreSQL не образуют общую транзакцию. После сбоя во время записи невозможно безопасно предположить, завершилась ли она. Поэтому повторная индексация такого занятия в той же области блокируется. `Archive.clone_for_rebuild` копирует оригиналы и поисковые фрагменты в новую область запуска без копирования состояний индексов; затем индексы нужно заново построить для этой области. Старые данные и неопределённая запись остаются нетронутыми. В синтетической проверке после имитации потери ответа от Neo4j Graphiti успешно построен в новой области, источники доступны, повторная загрузка не создаёт дубликатов. Восстановление Mem0 после аналогичного сбоя отдельно ещё не проверено.

Заметки для НИРС и фактический статус измерений находятся в [обзоре исследования](../../../../nirs/38_personal_memory_experiment.md).
