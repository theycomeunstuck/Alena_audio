# 4 этап ЗБР — индивидуальные задания

Четвёртый (индивидуальный) этап урока из презентации «ЗБР_Сценарий урока»:
групповое расследование закончилось, и каждый ребёнок получает именную
карточку-задание, собранную под то, что он любит, и под то, что он сейчас умеет.

Это делают две команды:

| Команда | Что делает |
|---|---|
| `scripts/make_task_card.py` | собирает карточки-задания для ребёнка или всей группы (часть 1) |
| `scripts/update_learner_card.py` | превращает заметки об уроке в обновления карточек (часть 2) |
| `scripts/check_material_coverage.py` | показывает темы учеников без учебного материала |
| `scripts/check_llm_contract.py` | измеряет, насколько модель соблюдает контракт |
| `learner-data/tools/zpd.py` | зона по каждой теме и объяснение почему |
| `learner-data/tools/progress_report.py` | отчёт о динамике ученика за период |

Всё, кроме двух команд с вызовом модели, работает без PostgreSQL и без LLM;
у обеих есть режим `--prompt-only`. Пошаговый сценарий — [HOWTO.md](HOWTO.md).

---

## Кто что решает

Главное архитектурное решение: **модель не решает педагогику и не пишет числа**.

| Решение | Кто принимает | Где код |
|---|---|---|
| какая тема, какая сложность, сколько ступеней подсказок | правило ЗБР по карте компетенций | `learner-data/tools/zpd.py` |
| какая математика допустима в задании | поиск по учебному материалу | `pipeline/retrieval.py` |
| сюжет, формулировки, тексты подсказок | LLM | `prompts/task_designer_prompt.txt` |
| mastery / independence после урока | код (EMA по уровню помощи) | `zpd.update_competency` |
| что записать в файл карточки | код + валидатор learner-data | `pipeline/card_updater.py` |

Поэтому результат воспроизводим: на одних и тех же наблюдениях числа получаются
одинаковыми, и репетитору можно объяснить, почему тема попала в ЗБР.

## Правило ЗБР (пункт 2 концепта, не пункт 3)

Зона выводится из **карты компетенций** (`learner_model.competencies`).
Отдельный блок `learner_model.zpd` — производная проекция: его перезаписывает
код, руками его не поддерживают.

```
mastery >= 0.85 и independence >= 0.80  ->  освоено (делает сам)
mastery <  0.30                          ->  пока за пределами ЗБР
иначе                                    ->  в ЗБР (делает с опорой)
mastery отсутствует                      ->  нет данных, тему не диагностировали
```

Высокая mastery при низкой самостоятельности остаётся **в зоне**: «умеет с
помощью, но не сам» — это и есть определение ЗБР по Выготскому.

Тема, которую ни разу не оценивали, в блок `zpd` не попадает вообще: про неё
нечего утверждать. То, что к ней не приступали, уже записано в
`knowledge[].status = not_started`. Если тему пробовали и она оказалась не по
силам — дайте ей запись в карте компетенций с низкой `mastery`, тогда она
появится в `outside`.

`knowledge[].status` тоже сверяется с картой компетенций, но мягко: внутри зоны
и `learning`, и `needs_support` считаются нормальными — это выбор репетитора.
Ругается валидатор только на противоречия: `not_started` у темы, которую уже
оценивали, и `confident` у темы, которую ребёнок сам ещё не делает.

Из зоны следует сложность задания и глубина лестницы подсказок:

| Зона | Сложность | Ступеней подсказок |
|---|---|---|
| освоено | hard | 1 |
| в ЗБР, mastery ≥ 0.60 | medium | 2 |
| в ЗБР, mastery < 0.60 | easy | 3 |
| за пределами ЗБР | easy | 3 |

Посмотреть зону ученика:

```bash
python learner-data/tools/zpd.py zvezdin-artem
python learner-data/tools/zpd.py zvezdin-artem --format json
python learner-data/tools/zpd.py zvezdin-artem --write   # перезаписать блок zpd в карточке
```

### Лестница подсказок

Из слайда «Цифровой скаффолдинг». Взрослый или ИИ спускается по ней только если
ребёнок не подхватил, и убирает опоры сразу, как только он справился.

| Ступень | Ключ | Что это | Зачёт в mastery |
|---|---|---|---|
| — | `independent` | решил сам | 1.0 |
| 1 | `hint_question` | наводящий вопрос | 0.7 |
| 2 | `visual` | визуальная опора, банк слов | 0.5 |
| 3 | `joint` | первый шаг сделали вместе | 0.25 |
| — | не справился | `solved: false` на любой ступени | 0.0 |

Подсказки лежат в карточке **отдельным полем**, а не внутри текста задания:
копия для ребёнка (`--format child`) их не содержит.

### Как считаются mastery и independence

```
mastery      = EMA(предыдущее, зачёт за попытку), alpha 0.4, априор 0.5
independence = EMA(предыдущее, решил ли совсем без подсказок), alpha 0.4, априор 0.5
confidence   = EMA(предыдущее, 1.0), т.е. сколько наблюдений стоит за оценкой
```

Следствия, которые проверяются тестами:

* одна удачная попытка — **не** освоение: mastery станет 0.70, тема остаётся в зоне;
* освоение засчитывается после **трёх** самостоятельных решений подряд (0.892);
* одна неудача не обнуляет историю: падение ограничено 0.15 за наблюдение;
* `needs_scaffolding` — производное поле, оно снимается автоматически.

Константы: `learner-data/tools/zpd.py`, раздел «Thresholds».

## Часть 1. Карточка-задание

```bash
cd TeachCopilot_RAG

# что уйдёт в модель — без вызова модели
python scripts/make_task_card.py zvezdin-artem --prompt-only

# карточка (нужна запущенная LLM: TEACHCOPILOT_CHAT_API_BASE_URL)
python scripts/make_task_card.py zvezdin-artem
python scripts/make_task_card.py zvezdin-artem --topic math.g3.geometry.point_line_ray_segment
python scripts/make_task_card.py zvezdin-artem --format child   # копия для ребёнка
python scripts/make_task_card.py zvezdin-artem --format json

# вся группа сразу и на печать
python scripts/make_task_card.py --all --format html --out cards.html
python scripts/make_task_card.py --learners zvezdin-artem,belka-06 --format html --out cards.html
```

Печатная форма (`pipeline/task_card_html.py`) кладёт сначала все детские
карточки, потом все листы для взрослого: стопку не нужно разбирать вручную. В
детском листе нет ни ответов, ни подсказок, ни служебного `topic_id`, зато есть
пустая строка под ответ. Если карточка не собралась для кого-то одного,
остальные всё равно делаются, а список неудач печатается в конце.

Без `--topic` тему выбирает правило ЗБР: сначала текущая цель из карточки, потом
первая тема в зоне.

### Что попадает в промпт

Проекция строится в `pipeline/learner_context.py::load_task_design_context` и
ограничена по составу и размеру:

* попадает: псевдоним, класс, тема и её зона, обоснование зоны, сложность,
  число ступеней, интересы (до 4), любимые сюжеты (до 2), стиль объяснения,
  сработавшие опоры (до 4), повторяющиеся ошибки по этой теме (до 3), чего
  избегать (до 3);
* **не попадает**: `legal_name`, журнал, баллы, темы, к которым задание не
  относится, полная карточка целиком.

Числа mastery в промпт не идут; в промпте есть словесное обоснование зоны.

### Учебный материал

`pipeline/retrieval.py` пробует три источника по очереди и возвращает первый
непустой:

1. pgvector через `pipeline.rag.search_knowledge`;
2. локальный JSON-индекс из `scripts/json_rag.py` (флаг `--index`);
3. лексический поиск по `knowledge-data/*.json` и `books/*.md` — только stdlib.

Третий уровень существует ради демонстрации на ноутбуке без сервисов. Источник
виден в выводе (`origin`), чтобы не путать полноценный векторный поиск с
запасным вариантом.

### Что проверяется в ответе модели

`parse_task_card` не доверяет ответу: тема, порядок и типы ступеней, количество
заданий восстанавливаются кодом, а расхождения попадают в поле `warnings` и
печатаются репетитору. Отдельно отмечается:

* служебная лексика в тексте для ребёнка («ЗБР», «mastery», `topic_id`);
* подсказка, содержащая готовый ответ;
* отсутствие задания, проверяющего типичную ошибку, если ошибки в профиле есть.

Жёсткая ошибка только одна: в ответе нет ни одного пригодного задания.

## Часть 2. Заметки об уроке → обновление JSON

```bash
# предпросмотр, ничего не пишется
python scripts/update_learner_card.py --learners zvezdin-artem --notes-file lesson.txt

# одна заметка на всю группу
python scripts/update_learner_card.py --learners zvezdin-artem,belka-06 --notes-file lesson.txt

# записать
python scripts/update_learner_card.py --learners zvezdin-artem --notes-file lesson.txt --apply

# режим «модель предлагает, репетитор подтверждает»
python scripts/update_learner_card.py --learners zvezdin-artem --notes-file lesson.txt \
    --mode tutor_confirmed --confirm math.g3.geometry.point_line_ray_segment --apply
```

Модель получает **ростер**: по каждому ученику — допустимые `topic_id` с их
зонами и уже известные формулировки ошибок. Всё, чего нет в ростере, отбрасывается
с замечанием, поэтому она не может выдумать тему или завести дубль ошибки.

Что обновляется:

| Поле карточки | Откуда |
|---|---|
| `learner_model.competencies[].mastery/independence/confidence/history` | код по уровню помощи |
| `learner_model.competencies[].effective_scaffolding` | что сработало на уроке |
| `learner_model.zpd` | пересчитывается из карты компетенций |
| `knowledge[].status` | правится только при противоречии с зоной; выбор «learning или needs_support» внутри зоны остаётся за репетитором |
| `error_patterns[]` | новая ошибка или +1 к счётчику существующей |
| `mvp.journal[]` | заметка репетитора за дату |
| `rag_context.recent_progress` | одна строка о продвижении |
| `rag_context.current_goal` | если в заметке сформулирована новая цель |
| `interests`, `mvp.story_preferences` | только добавление |

Не обновляется моделью никогда: `legal_name`, `mvp.points_ledger` (баллы
начисляет человек), `schema_version`, идентификаторы.

### Режимы (`TEACHCOPILOT_MASTERY_MODE`)

* `auto_ema` (по умолчанию) — наблюдения применяются сразу;
* `tutor_confirmed` — числа считаются и показываются как предложение, применяются
  только подтверждённые темы (`--confirm topic_id,...` или `--confirm all`).
  Факты — журнал, ошибки, прогресс — записываются в обоих режимах.

### Защита от порчи данных

Перед записью карточка целиком проходит валидацию learner-data. Если обновление
её ломает, файл не трогается и команда завершается с ошибкой.

### Повторное применение

Одни и те же заметки, применённые дважды за день, не сдвинут освоение второй раз
и не накрутят счётчики ошибок. Повтор распознаётся по двум признакам: в журнале
уже есть такая запись за сегодня, либо все наблюдения уже записаны сегодня с тем
же уровнем помощи. Если запись действительно нужна ещё раз — `--force`.

На следующий день те же заметки применятся нормально: «то же самое на следующем
занятии» — обычная ситуация, а не ошибка.

## Отчёт о динамике

```bash
python learner-data/tools/progress_report.py zvezdin-artem
python learner-data/tools/progress_report.py zvezdin-artem --since 2026-07-01 --format json
```

Читает `learner_model.competencies[].history` и отвечает на вопрос «что
изменилось»: насколько выросло освоение, стало ли нужно меньше помощи, сколько
было наблюдений, какие ошибки ещё повторяются. Формулировки про наблюдаемое
поведение, а не про способности ребёнка.

## Учебный материал и модель

```bash
# темы учеников без материала — генерация по ним пойдёт без опоры на программу
python scripts/check_material_coverage.py

# насколько конкретная модель соблюдает контракт (нужна работающая LLM)
python scripts/check_llm_contract.py --runs 5
```

Контракт-тест прогоняет генерацию N раз и показывает долю чистых прогонов и то,
что модель нарушает чаще всего: не то число ступеней, подсказка с ответом, чужая
тема, служебная лексика в тексте ребёнку. По результатам сначала правят
`prompts/task_designer_prompt.txt` и только потом меняют модель.

## HTTP

```bash
curl -X POST http://127.0.0.1:8099/task/design \
  -H "Content-Type: application/json" \
  -d '{"learner_id":"zvezdin-artem","count":3}'

curl -X POST http://127.0.0.1:8099/learner/update \
  -H "Content-Type: application/json" \
  -d '{"learner_ids":["zvezdin-artem"],"notes":"Луч начертил после наводящего вопроса...","apply":false}'
```

`/task/design` возвращает `card`, `text_for_child` и `text_for_tutor`.
`/learner/update` возвращает только диффы, полные карточки наружу не отдаются.


| Файл | Что проверяет |
|---|---|
| `tests/test_task_designer.py` | проекция, поиск материала, разбор и починка ответа модели |
| `tests/test_card_updater.py` | ростер, наблюдения → числа, режимы, повтор, запись в файл |
| `tests/test_task_card_html.py` | печатная форма: что видит ребёнок и что взрослый |
| `tests/test_material_coverage.py` | покрытие тем учеников учебным материалом |
| `tests/test_llm_contract_check.py` | агрегация контракт-теста |

Всё работает без БД, без эмбеддингов и без LLM: модель подменяется фейком, поиск
падает на лексический уровень. Исключение — `test_server_contract.py` и
`test_json_rag.py`, им нужны `fastapi` и эмбеддинги.
