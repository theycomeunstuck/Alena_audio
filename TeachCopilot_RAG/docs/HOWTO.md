# Инструкция: как этим пользоваться

Практический сценарий «урок за уроком». Теория и правила — в
[ZPD_STAGE4.md](ZPD_STAGE4.md), здесь только команды.

Все команды запускаются из папки `TeachCopilot_RAG`, кроме тех, что начинаются
с `python learner-data/...` — их запускают из корня проекта.

---

## Что нужно установить

| Что | Зачем | Обязательно? |
|---|---|---|
| Python 3.12 | всё остальное | да |
| `pip install -r requirements.txt` | сервер, поиск, эмбеддинги | для сервера и pgvector |
| LM Studio (или другой OpenAI-совместимый рантайм) | генерация карточек, разбор заметок | только для команд с LLM |
| PostgreSQL + pgvector | «взрослый» векторный поиск | нет, есть локальные запасные варианты |

Работает без всего этого (только Python):

```bash
python learner-data/tools/validate.py --strict     # проверить карточки учеников
python learner-data/tools/zpd.py <ученик>          # зона по каждой теме и почему
python learner-data/tools/progress_report.py <ученик>   # что изменилось за период
python scripts/check_material_coverage.py          # хватает ли учебного материала
python scripts/make_task_card.py <ученик> --prompt-only  # что уйдёт в модель
```

## Куда подключать модель

Настройки читаются из `.env` в корне проекта или в `TeachCopilot_RAG/`
(python-dotenv не обязателен, файл читается и без него). Провайдер задаётся
одним именем — адрес и модель по умолчанию подставятся сами:

```ini
# локальный LM Studio — по умолчанию, ключ не нужен
AI_PROVIDER=lmstudio

# облачный провайдер
AI_PROVIDER=deepseek
AI_API_KEY=sk-...
```

Известные имена: `lmstudio`, `deepseek`, `openai`, `openrouter`, `groq`,
`together`, `mistral`. Что угодно другое задаётся вручную:

```ini
TEACHCOPILOT_CHAT_API_BASE_URL=https://.../v1
TEACHCOPILOT_CHAT_MODEL=qwen/qwen3-8b
```

**Ключ не коммитить.** `.env` в `.gitignore`; в выводе команд ключ не
печатается.

Полезные переключатели:

| Переменная | Зачем |
|---|---|
| `TEACHCOPILOT_JSON_MODE` | `auto` (по умолчанию) просит строгий JSON и откатывается, если рантайм не умеет; `off` — только текстовый контракт |
| `TEACHCOPILOT_CONTRACT_RETRIES` | сколько раз переспросить модель при нарушении контракта, по умолчанию 1 |
| `TEACHCOPILOT_ROSTER_BATCH` | сколько учеников уходит в один запрос при разборе заметок, по умолчанию 5 |

## Шаг 0. Завести нового ученика

Опишите ребёнка как рассказали бы коллеге:

```bash
python scripts/create_learner_card.py --description "Миша, 4 класс, 10 лет.
    Любит динозавров и майнкрафт. Деление столбиком не идёт — теряет ноль в частном.
    Многозначные числа читает уверенно. Если не понял — сразу бросает, нужен пример."
```

Команда покажет черновик: интересы, темы со статусами, типичные ошибки, учебную
цель. Оценки освоения намеренно не заполняются — их посчитает код после первого
занятия. Проверьте и повторите с `--apply`.

## Группы

Чтобы не перечислять учеников руками, заведите группу в
`learner-data/groups/<id>.json`:

```json
{"schema_version": 1, "group_id": "detektivy-3", "title": "Детективное агентство, 3 класс",
 "learner_ids": ["zvezdin-artem", "belka-06", "lisa-03"]}
```

Дальше везде работает `--group detektivy-3` вместо `--learners a,b,c`.

## Шаг 1. Перед уроком: посмотреть, где ребёнок сейчас

```bash
python learner-data/tools/zpd.py zvezdin-artem
```

Покажет по каждой теме зону, освоение, самостоятельность и объяснение, почему
тема попала именно в эту зону. Это же правило потом выбирает сложность задания.

---

## Шаг 2. Собрать индивидуальные задания (4 этап)

Одному ребёнку, с ответами и подсказками для взрослого:

```bash
python scripts/make_task_card.py zvezdin-artem
```

Только задания, чтобы отдать ребёнку:

```bash
python scripts/make_task_card.py zvezdin-artem --format child
```

Всей группе сразу и на печать (сначала детские карточки, потом листы взрослого):

```bash
python scripts/make_task_card.py --all --format html --out cards.html
python scripts/make_task_card.py --learners zvezdin-artem,belka-06 --format html --out cards.html
```

Тему по умолчанию выбирает правило ЗБР (текущая цель, затем зона). Задать
вручную:

```bash
python scripts/make_task_card.py zvezdin-artem --topic math.g3.geometry.point_line_ray_segment
```

Если модель недоступна или хочется просто посмотреть, что ей отправят:

```bash
python scripts/make_task_card.py zvezdin-artem --prompt-only
```

**Что смотреть в результате.** В конце листа для взрослого печатается блок
«Замечания к сгенерированной карточке». Это то, что модель сделала не по
контракту и что код починил за неё: не то число подсказок, чужая тема,
подсказка с готовым ответом. Пустой блок — карточку можно давать как есть.

## Шаг 3. После урока: записать итоги

Репетитор пишет заметки как удобно — одним текстом на всю группу или отдельно
про каждого:

```text
Урок 26 июля, тема линии.
Тёма: луч начертил сам после наводящего вопроса, но опять поставил вторую точку
на конце. Помогло сравнение с фонариком.
Белка: кратное сравнение сегодня без подсказок, три задачи подряд.
```

Сначала предпросмотр — файлы не меняются:

```bash
python scripts/update_learner_card.py --learners zvezdin-artem,belka-06 --notes-file lesson.txt
```

Вывод — список изменений: как сдвинулось освоение, какие ошибки повторились,
что попадёт в журнал. Если всё верно:

```bash
python scripts/update_learner_card.py --learners zvezdin-artem,belka-06 --notes-file lesson.txt --apply
```

Повторный запуск тех же заметок в тот же день **не** применится второй раз:
команда скажет, что итоги уже записаны. Если запись действительно нужна ещё
раз — добавьте `--force`.

Можно пройти по пунктам разбора и принять их по одному:

```bash
python scripts/update_learner_card.py --group detektivy-3 --notes-file lesson.txt     --interactive --apply
```

Перед каждой записью команда спросит: принять наблюдение, ошибку, запись в
журнал. Enter — принять, `n` — отклонить.

Если в заметке названа длительность («занимались 45 минут»), она попадёт в
журнал занятий: дата, темы, минуты. По нему считается статистика в отчёте.

Перед записью делается резервная копия карточки в `learner-data/.backups/` —
последние 10 версий на ученика.

Если хотите подтверждать оценки вручную:

```bash
python scripts/update_learner_card.py --learners zvezdin-artem --notes-file lesson.txt \
    --mode tutor_confirmed --confirm math.g3.geometry.point_line_ray_segment --apply
```

В этом режиме журнал, ошибки и заметка о прогрессе пишутся всегда, а числа
освоения — только по подтверждённым темам. `--confirm all` подтверждает все.

## Шаг 4. Отчёт для родителя или для себя

```bash
python learner-data/tools/progress_report.py zvezdin-artem
python learner-data/tools/progress_report.py zvezdin-artem --since 2026-07-01
```

Показывает по каждой теме: как изменилось освоение, стало ли нужно меньше
помощи, сколько было наблюдений, какие ошибки ещё повторяются, что записано в
журнале и сколько баллов набрано.

## Добавить нового ученика

1. Скопируйте `learner-data/learners/_TEMPLATE.json` в
   `learner-data/learners/<id>.json` (id — латиницей, строчными, через дефис).
2. Заполните по [MANUAL.md](../../learner-data/MANUAL.md). `learner_model.zpd`
   руками **не** заполняйте — он выводится из карты компетенций.
3. Проверьте: `python learner-data/tools/validate.py --strict`.
4. Проверьте, что под темы ребёнка есть материал:
   `python scripts/check_material_coverage.py`. Если появился пробел —
   добавьте задачи, иначе задания будут собираться без опоры на программу.

---

## Добавить учебный материал

См. [knowledge-data/README.md](../knowledge-data/README.md). Коротко: JSON-файл
с массивом `tasks`, у каждой задачи `topic_id` из каталога, `grade`, `content`,
`answer`. После добавления — `python scripts/check_material_coverage.py`.

## Когда появится LM Studio

Первым делом стоит проверить, насколько выбранная модель соблюдает контракт:

```bash
python scripts/check_llm_contract.py --runs 5
python scripts/check_llm_contract.py --learners zvezdin-artem,ivanov-ivan --runs 3 --format json
```

Отчёт покажет долю чистых прогонов и что модель нарушает чаще всего. Если доля
низкая — сначала правьте `prompts/task_designer_prompt.txt`, потом уже меняйте
модель.

## Подводные камни

### Что система ловит сама

Об этом можно не думать — но полезно знать, что происходит.

| Что могло пойти не так | Что делает система |
|---|---|
| Модель выдала задачу с неверным счётом | Считает равенства в тексте и пишет «проверьте счёт — «8 · 5 = 45» не сходится (40 = 45)». Проверено на 123 задачах банка: ложных тревог нет |
| Сюжет не имеет отношения к интересам ребёнка | Замечание «сюжет не опирается на интересы ребёнка» с перечислением, что было проигнорировано |
| Промпт не влезает в контекст модели | Предупреждение с оценкой размера и напоминанием про окно 8192 |
| Ростер на 17 человек путает детей местами | Группа автоматически разбивается на запросы по 5 учеников (`--batch` меняет размер) |
| Модель приписала теме чужой класс | Наблюдение отбрасывается с замечанием |
| Думающая модель оставила `content` пустым | Ответ ищется в `reasoning_content`, с предупреждением про `/no_think` |
| `> cards.html` в PowerShell портит кодировку | `--format html` без `--out` не запускается и объясняет почему |
| Одни и те же итоги применены дважды | Повтор распознаётся, изменения не применяются; обходится через `--force` |
| Оценка по теме давно устарела | Пометка «тему не проверяли N дней» в отчёте, в `zpd.py` и в промпте генератора |
| Ctrl+C посреди прогона на группу | Уже собранные карточки сохраняются |
| Полная карточка с ФИО выведена в консоль | `build_context.py --format json` печатает предупреждение |

### Что всё равно остаётся на вас

**1. Педагогическая корректность задания.** Проверка счёта ловит неверные
равенства, но не ловит невыполнимое условие, двусмысленную формулировку или
задачу не по теме. **Прочитайте карточку перед тем, как отдать её ребёнку** —
лист для взрослого печатается с ответами именно для этого.

**2. Окно контекста модели.** Система предупредит, но поставить 8192 вместо
дефолтных 4096 нужно руками в LM Studio. Замеры: карточка-задание ~2 400
токенов, обновление на 5 учеников ~2 000.

**3. Скорость на группе.** `--all` — это 17 последовательных вызовов модели,
без параллельности. С думающей моделью это десятки минут. Прерывание сохраняет
собранное, но продолжить с места обрыва нельзя — только запустить заново.

**4. Предпросмотр перед `--apply`.** Команда по умолчанию ничего не пишет и
показывает список изменений. Это не формальность: модель может неверно понять
заметку, и увидеть это можно только глазами.

**5. Автокоррекция статуса темы.** Если статус противоречит зоне
(`not_started` у темы с оценкой, `confident` у темы, которую ребёнок сам не
делает), обновление его исправит. Различие между `learning` и `needs_support`
внутри зоны — ваше и не трогается.

**6. У освоения нет забывания.** `mastery` не убывает само по себе. Система
пометит, что тему не проверяли больше месяца, но занижать оценку без реального
наблюдения не станет — это была бы выдумка.

**7. Персональные данные.** В репозитории только вымышленные дети. Реальные
ФИО, контакты и записи занятий здесь хранить нельзя, тем более в публичном
GitHub.

**8. Мелочи, которые ломают валидацию.**

- `learner_id` обязан совпадать с именем файла; переименование рвёт историю.
- Псевдонимы уникальны: второго «Артёма» валидатор не пропустит.
- Даты берутся с часов машины. Сбитые часы = неверные даты в журнале и
  сломанная защита от повторного применения заметок.
- Добавили ученика на новой теме — добавьте и материал, иначе упадёт
  `check_material_coverage.py`.

## Проверки перед коммитом

```bash
python learner-data/tools/validate.py --strict
python learner-data/tools/selftest.py
cd TeachCopilot_RAG && pytest tests/ -q
python scripts/check_material_coverage.py
```

Первые четыре работают без БД, эмбеддингов и LLM.
