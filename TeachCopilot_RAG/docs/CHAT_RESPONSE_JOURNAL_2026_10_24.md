# Локальный журнал сырых ответов обычного чата

Прямой `/v1/chat/completions` теперь сохраняет полученные ответы независимо
от PostgreSQL. Для этого используется отдельный SQLite-файл
`.local/chat-responses.sqlite3`, настройка – `LOCAL_CHAT_RESPONSE_JOURNAL`.
Пустой путь не выключает защиту: запрос завершается с HTTP 503.

Журнал worker `.local/memory-worker-responses.sqlite3` сохраняет свой формат
и назначение. Файлы журналов друг друга не принимают и не преобразуют.

## Что и когда сохраняется

1. После авторизации, проверки сеанса и обработки повторной выдачи создаётся
   локальная запись обычного запроса с серверными идентификаторами.
2. До каждого фактического вызова модели фиксируется подготовка вызова.
3. Локальный ответ Ollama записывается сразу после чтения JSON, до проверки
   содержимого, нормализации текста и расчёта бюджета. При невалидном JSON,
   нечисловых значениях `NaN`/`Infinity` и HTTP-ошибке сохраняется доступное
   исходное тело ответа. Ответы resolver, выбора операции и локальной проверки
   приватности входят в ту же цепочку запроса.
4. Для внешнего адаптера тело ответа сохраняется до разбора, расчёта бюджета,
   проверки завершённости и замены псевдонимов источников. Отражённый API-ключ,
   включая вложенное JSON-экранирование, удаляется. Глубоко вложенные варианты,
   которые нельзя проверить с ограниченной работой, консервативно скрываются.
   Это не включает новые внешние запросы и не меняет прежние денежные журналы.
5. Полный внутренний результат RAG сохраняется отдельно до удаления
   `_local_diagnostics`, публичной проекции и записи завершения в PostgreSQL.
   Так же сохраняются ответы внедрённых адаптеров и детерминированные ответы
   обычного чата.

SQLite использует `synchronous=FULL`, отдельные соединения и короткие транзакции.
Запросы, вызовы и исходы защищены от изменения и удаления. Повтор той же записи
допускается только с идентичным содержимым. Одновременные процессы получают
разные идентификаторы и последовательные номера вызовов внутри запроса.

Привязка к HTTP-запросу использует `ContextVar`. Общие объекты runtime и RAG
не получают изменяемых callbacks для отдельного ученика. Контекст сбрасывается
при успехе и исключении; работа worker вне этого контекста сохраняет прежний
порядок записи.

## Отказы и повторная выдача

При отказе журнала до вызова модель не вызывается. При отказе после ответа
следующие вызовы и успешная выдача запрещены; перехват ошибки во вложенном
fallback не снимает блокировку. Ученик получает общее сообщение HTTP 503 без
пути файла, текста ответа или внутренних идентификаторов.

При потере подтверждения PostgreSQL API не выполняет вторую завершающую запись.
Если сообщение уже сохранено, штатный повтор возвращает прежний публичный ответ.
Если результат не сохранён, остаётся блокирующая запись `pending`, которая после
штатного истечения аренды переходит в `unknown_outcome`. Сбой попытки записи
обычного отказа также не скрывает первоначальную ошибку. Ни один из этих случаев
не запускает повторную генерацию.

Журнал не восстанавливает PostgreSQL, не завершает задания и не подменяет ответ
сеанса. Повторная выдача из PostgreSQL не создаёт новых записей журнала.
Автономные и явные арифметические действия не входят в этот журнал обычного чата.
Legacy-клиенты без сеанса сохраняют прежний контракт и отдельный серверный ID
запроса; журнал не добавляет им новый протокол идемпотентности.

## Приватность и чтение

В журнале хранятся отпечаток БД, ID аккаунта и ученика, задания, сеанса и сообщения,
назначение вызова, время и полный полученный ответ. Запросы к модели, заголовки,
DSN, пароль и ключ авторизации туда не записываются. Сам ответ может содержать
частный текст, поэтому файл остаётся локальным в игнорируемой Git папке `.local`.
HTTP, ученический архив и повторная выдача не получают новых полей журнала.

Команда читает только выбранные записи, не подключаясь к PostgreSQL или модели:

```powershell
.\.venv-local\Scripts\python.exe scripts/inspect_chat_responses.py --job-id JOB_ID
.\.venv-local\Scripts\python.exe scripts/inspect_chat_responses.py --learning-session-id SESSION_ID --client-message-id MESSAGE_ID
.\.venv-local\Scripts\python.exe scripts/inspect_chat_responses.py --call-id CALL_ID --include-response
```

Доступны также `--request-id` и явный `--journal`. По умолчанию выводятся только
метаданные; полный ответ требует `--include-response`. Привязка к текущей БД
проверяется по тому же отпечатку, что у worker. Чужой или повреждённый SQLite-файл
не изменяется. Автоматического импорта, повтора генерации и удаления истории нет.

## Проверки и границы

Целевые проверки охватывают фиксацию до публичной проекции, ошибки подтверждения
до и после commit, повтор без генерации, двойной отказ очистки, восстановление
после истечения аренды, настоящий разрыв TCP-соединения с временной PostgreSQL
после ответа и чтение журнала отдельным процессом при недоступной БД.
Дополнительно проверяются malformed/truncated JSON, внутренние поля модели,
невалидный resolver, расчёт бюджета после получения ответа, отказы журнала,
параллельные процессы и контексты, Unicode, подмена БД, приватность CLI и исключение
автономных действий. Внешний адаптер использует только управляемый HTTP-транспорт
и временные денежные журналы. Реальных генераций, embeddings и оплачиваемых
запросов в проверках нет.

В полный набор включены **92 новые целевые проверки**. После последних изменений
`scripts/verify_local.py --ui` прошёл: **1705 pytest-тестов и 52 проверки карточки,
0 пропусков**, включая браузер. Pytest завершился за 773,37 секунды с одним
прежним предупреждением Starlette о тестовом клиенте. Отдельно прошли 270 проверок
чата и адаптеров и дополнительная регрессия адаптера, runtime и хранения.

Итоговые логи и отчёт находятся в `.local/chat_response_journal_20261024/full02/`.
Сверены хеши 14 исходников, проверенных этим запуском. Квитанция
`.local/chat_response_journal_20261024/final_preservation.json` подтверждает
неизменность всех 28 таблиц рабочей БД, `.local.env` и журнала рабочего worker.
Сохранены 31 завершённое задание и 4 неизвестных исхода; прежний worker PID 31416
продолжает работу, API отвечает HTTP 200. Временных проверочных БД не осталось.

Первый общий запуск `full01` прервался при перезапуске сервера агента и не считается
итоговым. В нём было также раннее падение браузерного сценария автономного деления;
его причина по оставшимся данным не установлена. В сценарий добавлено сохранение
traceback в локальные артефакты. Отдельный повтор шести занятий и окончательный
полный набор прошли. Первоначальные артефакты сохранены, очистка трёх оставшихся
временных БД записана отдельно с проверкой точных имён, владельца и отсутствия
подключений. Браузерная квитанция полного повтора находится в
`full02/browser/27129d31a13e/receipt.json`: 6 занятий, 99 действий, 0 обращений
к запрещённым сервисам.

Гарантия зависит от успешной локальной фиксации. Завершение процесса между
получением HTTP-ответа и SQLite commit, отказ носителя или ответ, который вообще
не дошёл до приложения, сохраняют окно потери. Для локального корректного JSON
хранится декодированный объект до проверки, а не точные HTTP-байты; для ошибки
хранится доступное тело. Внешнее тело хранится после удаления отражённого ключа.

Рабочие API и worker в рамках этой реализации не перезапускались. Рабочая защита
прямого чата начнёт действовать после обновления API. На рабочем стенде остаётся
схема 12; при обновлении API необходимо штатно применить уже существующую миграцию
013 предыдущего этапа. Новый журнал чата сам не требует изменения PostgreSQL.
Результаты НИРС, замороженные материалы, закрытые журналы и документы Word/PPT
сохраняются.
