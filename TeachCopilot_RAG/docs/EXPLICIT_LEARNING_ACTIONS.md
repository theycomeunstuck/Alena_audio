# Явные учебные действия в чате

В режиме ученика под перепиской появился выбор «Что сделать». Доступны четыре действия: «Проверить деление», «Разряды частного», «Дать пример» и «Вывод Python». Они вызывают локальные вычислители напрямую. Модель не распознаёт намерение и не пишет вычисленный ответ.

## Как пользоваться

Откройте `http://127.0.0.1:8099`, войдите как ученик и выберите предмет. В математике доступны три действия с делением, в Python и программировании – вывод `print`. На телефоне сначала откройте вкладку «Занятие». Для смены предмета завершите текущее занятие.

«Проверить деление» принимает делимое от 0 до 999999 и делитель от 1 до 99. Поле «Мой ответ» необязательно. Действие показывает весь результат и проверку умножением. При остатке записанное равенство без остатка не признаётся верным. «Разряды частного» также раскрывает результат, затем объясняет значения его цифр.

«Дать пример» предлагает деление без остатка с трёхзначным частным вида `a0b`, где обе крайние цифры ненулевые. Можно выбрать разрядность делителя. Ответ не включается ни в текст упражнения, ни в метаданные. При подборе исключаются примеры из последних 40 серверных сообщений, до 4000 символов каждого; повторение за этой границей возможно.

«Вывод Python» принимает полный исходный код до 4000 символов. Поддерживаются 1–8 прямых вызовов `print` с литералами строк, целых чисел, `bool`, `None` и параметрами `sep`/`end`. Выражения, переменные, импорты и выполнение программ не поддерживаются. Пример `print(1 + 2)` получает явный отказ; можно исправить его в той же форме. Вычислитель разбирает AST, не использует `eval` или `exec`. Вывод показывается как простой текст с сохранением пробелов, кавычек и переводов строк, до 8192 символов.

## API и сохранение

Прежний `POST /v1/chat/completions` сохраняется. Новая ветка включается только наличием верхнеуровневого поля `learning_action`:

```json
{
  "learning_session_id": "идентификатор текущего занятия",
  "client_message_id": "уникальный идентификатор запроса",
  "messages": [],
  "metadata": {"subject_id": "math"},
  "learning_action": {
    "operation": "division_check",
    "dividend": 7560,
    "divisor": 24,
    "stated_quotient": 315
  }
}
```

Другие действия:

| Операция | Поля |
| --- | --- |
| `division_places` | `dividend`, `divisor` |
| `division_practice` | необязательный `divisor_digits`: 0, 1 или 2; по умолчанию 0 |
| `print_output` | `code`: исходный текст без исправлений |

Числа должны быть целыми JSON-числами: строки, дробные числа и `bool` отвергаются. Лишние поля и неизвестные действия также отвергаются. `messages` можно опустить либо передать пустым массивом; непустая или некорректная история получает HTTP 422. Нельзя добавить свободные условия и молча потерять их при вычислении. Ошибка явного действия никогда не переключает запрос на модель.

Сервер проверяет аккаунт, ученика, владельца учебной сессии и её предмет до возврата сохранённого ответа. Произвольный префикс `math.*` не даёт доступ к математическим действиям: полная тема должна существовать в каталоге. Предмет из `metadata` не может переопределить предмет сессии.

Сервер формирует однозначный текст запроса из проверенных полей, сохраняет его как реплику ученика и отдельно сохраняет ответ ассистента. Код сохраняется буквально. Повтор с тем же ID возвращает прежний ответ, включая после перезапуска приложения и завершения занятия. Изменение параметров или смена обычного чата на явное действие при том же ID даёт HTTP 409. В браузере при потере ответа поля блокируются, а повтор отправляет неизменный запрос.

Используются существующие устойчивые задания чата, ограничения очереди, ревизии и хранилище PostgreSQL. Для явного действия не устанавливается признак начала модельного вызова. Нужна работающая БД; занятость очереди или изменение контекста могут привести к диагностируемому отказу. Отдельной миграции нет.

Успешный ответ содержит `learning_action.version=explicit-learning-action-v1`, `learning_tool.status=verified`, точную область проверки и `usage_scope=deterministic_action_no_model_calls`. Вызовов классификатора, селектора, RAG, embeddings и внешнего провайдера в этой ветке нет. `student_competence_assessed=false`: получение ответа не доказывает навык ученика. Завершение занятия ставит прежнее обновление памяти в очередь; предположения о навыках по-прежнему требуют преподавательского просмотра.

## Проверки и ограничения

Воспроизведение из `TeachCopilot_RAG`:

```powershell
.venv-local/Scripts/python.exe scripts/verify_local.py --ui
```

Проверяются ошибочные поля, остаток, точность разрядов, свойства упражнений и отсутствие ответа в метаданных, буквальное сохранение кода, изоляция и предмет сессии, повтор и конфликт ID. Тесты PostgreSQL проверяют сохранённые источники, повтор после перезапуска и завершения занятия, отсутствие изменений компетенций и недоступность кэша другому аккаунту. Браузерные сценарии используют настоящий HTTP API с синтетическим хранилищем, проверяют все четыре действия, потерю ответа после его сохранения сервером, исправление отказа, клавиатуру, экраны 390/320 px и безопасный показ HTML как текста. Границы модели и поиска заменены объектами, которые немедленно падают при вызове.

Это проверка конкретных детерминированных действий. Качество обычного свободного диалога, произвольных программ Python и педагогическая полезность упражнений этим не установлены. Экспериментальный модельный селектор остаётся выключенным по умолчанию. Формальная содержательная оценка исследования памяти остаётся `not_assessed` после калибровки 23/24. Рабочая память – `tail`; архивы прошлых опытов не изменялись.
