# Восстановление опроса очереди после потери PostgreSQL

Продолжение после `146de01`, код – `00bf000`. Прежний рабочий worker завершался при обрыве PostgreSQL: ошибка из захвата задания выходила из основного цикла без обработки. Дополнительно ошибка подтверждения записи результата попадала в общий обработчик, который пытался записать обычный отказ через второе завершение задания.

## Поведение

Непрерывный `scripts/memory_worker.py` после `psycopg2.OperationalError` или `InterfaceError` продолжает опрос очереди. Задержка начинается со значения `--idle-seconds`, удваивается до 30 секунд и сбрасывается после успешного обращения. В журнале видны недоступность БД и возобновление опроса. Текст исключения подключения не печатается, чтобы не раскрыть параметры соединения.

Повторяется только опрос очереди. Worker не запускает заново сохранённый в памяти запрос и не снимает аренду задания вручную. В `MemoryWorker.run_once` и извлечении интересов ошибки БД передаются наружу без второго завершения и без скрытия ошибки в необязательном черновике.

В конечном режиме `--max-jobs` ошибка БД завершает worker с кодом 1; пакет не получает скрытых повторов или продления. Ошибки SQL класса `ProgrammingError` и обычные программные ошибки основным циклом не скрываются.

| Момент потери связи или подтверждения | Результат |
| --- | --- |
| До захвата задания | Следующий опрос может получить ещё не начатое задание. |
| До фиксации захвата | Транзакция откатывается, задание остаётся в очереди. |
| После фиксации захвата, без маркера вызова | Сохраняется `running`; возврат в очередь только после истечения штатной аренды. |
| До фиксации маркера вызова | Модель не вызывается; отсутствие сохранённого маркера допускает штатное восстановление после аренды. |
| После фиксации маркера, до получения подтверждения | Модель не вызывается; сохранённый маркер консервативно приводит к `unknown_outcome` после аренды. |
| После ответа, до фиксации результата | Один вызов; незавершённое задание становится `unknown_outcome` после аренды. |
| После фиксации результата, без подтверждения | Сохраняются `completed` и одна версия памяти; нового вызова нет. |

Все данные синтетические. Каждый сценарий очереди имеет отдельную временную БД; её удаление ограничено проверенным случайным именем. Для сетевого сбоя отключается только соединение дочернего процесса через тестовый TCP-переход. Рабочий PostgreSQL не останавливается. Ответы модели управляемые, реальных локальных генераций, embedding-вызовов и оплачиваемых запросов нет. Ollama для проверок направлен на недоступный порт.

## Ограничения

30 секунд – предел задержки между попытками, а не общий срок восстановления. Эта правка не задаёт новые `connect_timeout` или `statement_timeout`. `OperationalError` шире временного обрыва: постоянная ошибка подключения тоже может поддерживать опрос до исправления конфигурации. Строки журнала не устанавливают временный характер причины.

Сырая генерация, оставшаяся только в `self.calls`, при недоступной БД может не сохраниться. Повторная генерация для восстановления диагностики не выполняется. Статус незавершённого задания определяется сохранённым маркером после истечения аренды, которая у worker составляет 600 секунд.

Проверка относится к устойчивости очереди и не подтверждает смысл рекомендаций или свободных ответов. Ошибка трактовки «4?» остаётся видимой для преподавательского просмотра. Исходный опыт, новый замороженный протокол НИРС, отрицательная калибровка и покрытие 0/128 сохраняются. Новых расходов нет; прежние дополнительные расходы с резервами – $0.49214646250. Закрытые денежные журналы не открываются. Официальные Word/PPT не перерабатываются.

## Воспроизведение и откат

Из корня проекта:

```powershell
.venv-local/Scripts/python.exe scripts/verify_local.py --ui
```

Новый модуль `tests/test_memory_worker_recovery.py` входит в полный набор. При отдельном запуске требуется `TEACHCOPILOT_TEST_DSN` для временной локальной PostgreSQL; без него интеграционные случаи пропускаются. Не указывайте рабочую учебную БД как тестовую.

Откат кода – `git revert 00bf000`; предыдущая точка – `146de01`. Откат не изменяет финансовые журналы и исследовательские результаты. Рабочие процессы обновляют только после проверки владельцев и свободной очереди. Push не выполняется.
