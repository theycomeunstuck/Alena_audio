# Ограниченная доработка после первого живого занятия

Первый пакет v1 выполнен: четыре чат-запроса. Реплика «хз» получила учебное уточнение, просьба про кометы снова привела к общей заглушке. В первом ответе помощник ошибочно предложил записать сверху общее число частей. Ответы сохранены дословно в `memory-continuation-v1-2026-10-19/lesson/`. Они не заменяются успешными ответами.

До следующей генерации уточнено одно правило production resolver: неопределённая смена сюжета после учебного вопроса требует учебного продолжения либо уточнения; сама по себе она не является запросом энциклопедических фактов. Явные неподдерживаемые и вредные запросы остаются за границей. Добавлено общее указание исправлять ошибочное предыдущее объяснение ассистента, а не принимать его за факт.

План v2 использует те же четыре реплики как повторную проверку разработки, не как новый независимый тест. Далее выполняются два сообщения после просмотра памяти и перезапуска, три граничных сообщения и одна рекомендация преподавателю. Общий предел обоих пакетов – 13 чат-запросов и одна рекомендация. Скрытых повторов нет. Вызовы локальные, исходные ответы v1 и старый исследовательский опыт остаются неизменными.

При просмотре синтетической памяти отдельно отметить ошибку помощника. При необходимости добавляется явная синтетическая заметка преподавателя с исправлением и источником, создаётся новый черновик. Это отдельное вмешательство ассистента, не человеческая оценка, не изменение исходной реплики и не подтверждение освоения учеником. Кандидаты интересов не принимаются автоматически.

В v2 получен один ответ, второй запрос завершился HTTP 503: проверка ошибочно запрещала совместный контекст исходного вопроса ученика и уточняющего вопроса ассистента. Ответ на запрос «хз» не получен, повтор не выполнялся; две оставшиеся реплики занятия не запускались. Это программная ошибка контракта, исправленная без повторной генерации первого занятия. Каждый указанный контекст теперь проверяется отдельно, их роли не объединяются в доказательства.

Прерванная сессия закрывается отдельно с сохранением отказа. После просмотра и отдельной синтетической учительской заметки создаётся новый черновик. Затем выполняются четыре сообщения новой сессии: два предусмотренных для recall и два ранее не выполненных коротких сообщения про кометы и «ага». С тремя граничными сообщениями общий предел остаётся 13 попыток чата. Начальные v1/v2 сохраняют собственные отрицательные результаты и пропущенные случаи, а новые сообщения не подменяют их.

Первый запрос recall v2 тоже завершился без ответа: модель указала индекс вопроса, хотя в новой сессии вопросов ещё нет. Схема ограничена фактически доступными индексами; отсутствующие типы контекста не предлагаются модели. Допустимый необязательный индекс при выключенном признаке использования не активирует этот контекст. Неверный индекс по-прежнему отклоняется. Это изменение проверки контракта, не восстановление ответа или повторная генерация.

Для заключительной проверки v3 заранее оставлены три сообщения новой сессии: «Я снова здесь. Какой один шаг по дробям мне сейчас сделать?», «хз», «ну вроде. а можно про кометы?». Вместе с тремя граничными запросами и семью уже предпринятыми попытками предел остаётся 13. Дополнительная настройка по содержательному результату не планируется. Пропущенные сообщения предыдущих фаз остаются отмеченными как невыполненные.

Первое сообщение v3 получило отказ: признак использования вопросов текущей сессии был включён при пустой сессии. Для отсутствующего контекста схема теперь ограничивает этот признак значением false. Невалидные решения сохраняются в диагностике серверного задания. После восьми попыток остаются два сообщения v4 («Продолжим прошлый круг, но можно теперь через кометы? Задай один вопрос.», «хз») и три граничных случая. Предел 13 не меняется. Это исправление программного контракта, а не новая настройка смыслового промпта.
