# Локальная база, учебный корпус и RAG

Локальный интерфейс учителя и ученика доступен по корневому адресу API. [Руководство пользователя](USER_GUIDE.md) и [расширенная приёмка](EXTENDED_VERIFICATION_2026_10_13.md) описывают актуальные сценарии. PostgreSQL хранит аккаунты, профили и учебный прогресс; RAG ищет материалы по математике, Scratch и Python. Полные карточки учеников не индексируются как учебный текст. Подробнее: [схема БД](LOCAL_SCHEMA.md).

Статус на 13.10.2026: локальная БД, импорт, резервное копирование, аутентификация, API и retrieval проверены. Сводка измерений и ограничения приведены ниже.

## Проверка доступа и ответа ученику

API отдаёт ученику только разрешённые поля карточки и безопасные метаданные найденных источников: ID, файл и версию источника, тему и оценку релевантности. ID источников сохраняются; raw snapshot, содержимое материалов и ключи ответов не входят в видимый ответ ученика. Для чата строится компактная обезличенная педагогическая проекция: псевдоним, класс, язык, интересы, цель, темы, недавний прогресс и трудности. Закрытые идентификаторы и tutor_notes исключены. Контекст планирования может использовать ограниченные учебные показатели, включая mastery/independence, для педагогической настройки.
## Что где хранится

- Аккаунты, роли, хеши паролей и сессии – локальный PostgreSQL. Один аккаунт педагога может иметь связь с несколькими учениками; ученик может иметь собственную учётную запись. Доступ к карточке идёт через явную связь аккаунт–ученик.
- Карточка ученика – JSON snapshot в таблице learners с прежним `learner_id`. Для демо миграции не меняйте эти ID.
- Текущая компетенция и история – отдельные записи компетенций/событий с `topic_id`, mastery, independence, уровнем поддержки и датой. Журнал, заметки, ошибки и баллы сохраняют исходные payload, чтобы не терять смысл при импорте.
- Каталог – предметные skill IDs. Существующие `math.g3.*` / `math.g4.*` остаются неизменными. Программирование использует `programming.scratch.*` и `programming.python.*`, `subject_id: programming`, `curriculum_id: programming-foundations-v1`. Класс является отдельной подсказкой, Python допускает `grade: null`.
- Учебные записи – отдельные `materials` с `subject_id`, `curriculum_id`, `topic_id`, источником, версией источника, embedding model/dimension и metadata. Материалы берутся из `knowledge-data/`; полный текст профиля туда не попадает.
- Индексы поиска строятся локально из одобренных материалов. После изменения текста или embedding модели старые embeddings нельзя смешивать с новыми – используйте новую версию/перестройте индекс.

`Store.migrate` применяет ожидающие SQL-файлы в числовом порядке под транзакционной advisory lock. Один вызов миграции работает в транзакции: при ошибке изменения вызова откатываются. Перед изменением существующей базы сделайте backup.
Повторный импорт сохраняет snapshot исходных файлов. Уже существующую карточку ученика импорт не перезаписывает: изменения пропускаются, а конфликт возвращается в отчёте. Материалы каталога синхронизируются по ID и версии исходного файла; правки в учебном JSON обновят соответствующие материалы.
## Демо-профили

Импортировано 17 демо-профилей со стабильными `learner_id`. В локальной базе уже заведены демо-аккаунты `teacher@local.test` и `student@local.test`; ученик привязан к карточке `ivanov-ivan`. Локальные пароли хранятся в игнорируемом Git файле `.local/credentials.json`; не копируйте его содержимое в документацию, логи или репозиторий. Новый teacher создаётся через `bootstrap`, которому пароль передаётся интерактивно. Эта команда назначает ему существующие карточки на момент создания; карточки, импортированные позже, назначаются явно через операторскую операцию `Store.assign_learner`.

Для импорта сначала проверьте, что JSON source valid, затем примените миграции и импортируйте репозиторий. CLI `scripts/manage_local.py` реализует команды migrate/import/bootstrap/export/backup/restore; точные параметры смотрите через `--help`. Ожидаемый базовый порядок:

```powershell
cd Alena_audio\TeachCopilot_RAG
$env:OLLAMA_NO_CLOUD = "1"
$env:OLLAMA_HOST = "127.0.0.1:11435"
.\scripts\setup_local.ps1 -DownloadRuntime
```


Локальные операции учётных записей, экспорта и резервного копирования:

```powershell
# Run from Alena_audio\TeachCopilot_RAG after setup_local.ps1
& .\.venv-local\Scripts\python.exe scripts/manage_local.py export --out .local/exports
& .\.venv-local\Scripts\python.exe scripts/manage_local.py backup --out .local/backups/teachcopilot.dump

docker exec teachcopilot_local_db createdb --username teachcopilot restore_target
& .\.venv-local\Scripts\python.exe scripts/manage_local.py restore --target-db restore_target --in .local/backups/teachcopilot.dump --yes
```

Экспорт и backup лежат в игнорируемом `.local/` внутри `TeachCopilot_RAG`. Compose публикует PostgreSQL контейнера `teachcopilot_local_db` на `127.0.0.1:5434` и использует named volume `local_database`. Restore требует пустую уже созданную базу в том же контейнере. Пример выше одноразовый и не удаляет существующую БД.

Для новых учётных записей используйте bootstrap CLI для реального педагога; пароль вводится интерактивно. Защитите диск и резервные копии. Локальный ПК не заменяет резервную копию.

## Учебный seed для Scratch и Python

`../../learner-data/catalog/programming.json` вводит 12 компетенций: шесть Scratch (последовательность, события, циклы, условия, переменные, отладка) и шесть Python (вывод, переменные, условия, циклы, списки, отладка). `../knowledge-data/programming_scratch.json` и `programming_python.json` содержат по два авторских задания на каждую компетенцию, ответы, лестницу подсказок и официальные ссылки на Scratch/Python. Формулировки написаны для проекта и не копируют длинные фрагменты документации.

Этот корпус – начальный курируемый набор, не полный курс программирования. Педагог должен проверить задания, возрастную уместность и ответы перед использованием с учениками. Добавляйте записи только с устойчивым task ID, стабильным skill ID, предметом/куррикулумом, сложностью и проверяемым ответом. Для Scratch полезны ответы в виде точных блоков/порядка блоков; для Python – исполняемый минимальный пример и ожидаемый вывод.

## Локальный запуск и автономность

Ollama слушает локальный интерфейс. Полностью локальный режим включается отключением cloud features; первый раз модели нужно скачать, поэтому pull требует интернета. После этого выключите cloud и проверьте отсутствие сетевой зависимости в локальном запросе: По умолчанию Ollama хранит модели в стандартном пользовательском каталоге `%USERPROFILE%\.ollama\models`. Не задавайте `OLLAMA_MODELS` на `.local` проекта, если не хотите изменить расположение моделей: `.local` игнорируется Git, но не является текущим cache path.

```powershell
$env:OLLAMA_NO_CLOUD = "1"
$env:OLLAMA_HOST = "127.0.0.1:11435"
ollama list
ollama run gemma4:12b
```

Выбранный локальный default для генерации – `gemma4:12b`, с embeddings `bge-m3`. Выбор основан на небольшом сравнении и независимом просмотре результатов; это рабочий default, а не доказательство глобально лучшей модели.

Embedding-only blind benchmark из `retrieval-blind.json` на 60 предметных запросах в двух прогонах: BGE-M3 Recall@3 100%, Qwen Embedding и MiniLM – по 98,333%. Средние задержки составили 59,5 / 61,77 / 38,8 мс соответственно. Эти числа описывают качество retrieval по материалам, а не обработку off-scope запросов.

Для локального чат API Ollama поддерживает OpenAI-compatible subset на `http://127.0.0.1:11435/v1`. Строгий structured output с JSON Schema документирован в локальном Ollama API через поле `format`; не рассчитывайте на полную совместимость всех OpenAI параметров. Для текущего прототипа главная модель должна выдавать учебный ответ, а не напрямую изменять БД. Изменение прогресса проходит через серверную проверку и подтверждение педагога.

В маршруте чата предмет остаётся неопределённым (`subject_id: null`), если запрос не содержит явного предмета или уверенно распознаваемых слов. `POST /rag/search` по умолчанию фильтрует `math`; явно заданный `math` остаётся жёстким фильтром. Scope gate оценивает запрос до embedding-поиска, а subject служит ему подсказкой. При невалидном JSON-решении запрос завершается ошибкой сервиса.

Ссылки на первичные источники: [Ollama local-only FAQ](https://docs.ollama.com/faq), [OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility), [structured outputs](https://docs.ollama.com/capabilities/structured-outputs), [Qwen3.5-9B model card](https://huggingface.co/Qwen/Qwen3.5-9B), [Gemma 4 12B model card](https://huggingface.co/google/gemma-4-12B), [Qwen3 Embedding card](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B), [BGE-M3 card](https://huggingface.co/BAAI/bge-m3), [Python tutorial](https://docs.python.org/3/tutorial/), [Scratch for Educators](https://scratch.mit.edu/educators/).

## Протокол оценки и результаты модели

`../tests/fixtures/local_rag_golden.json` содержит 20 math, 20 Scratch, 20 Python и 15 неподдерживаемых/адверсариальных запросов. Ожидаемые источники и skills указаны явно; неподдерживаемые кейсы проверяют abstention, а не точность похожести.

Retrieval уже измерен по замороженному набору запросов; повторите тот же протокол на большем корпусе реальных учебных материалов и отдельно по предметам. Генерацию сравнивайте на одинаковых запросах и контексте: проверяйте правильность ответа, объяснение на русском, Scratch-блоки/Python-код, отсутствие готового решения в подсказке, JSON и задержку. Сверяйте ответы с reference/checklist из seed-записей, проводите слепую оценку педагогом и фиксируйте digest модели, quantization, параметры, время и peak VRAM/RAM.

## Результаты выбора локальных моделей

На слепом наборе из 150 генерационных запросов на модель Gemma 4 12B показала среднюю задержку 1520,97 мс и долю ответов с ожидаемой ссылкой на источник 0,90; Qwen 3.5 9B – 1764,38 мс и 0,40. Покрытие ключевыми словами составило 0,610 у Gemma и 0,573 у Qwen; это лексическая метрика, не оценка фактической правильности.

Независимый просмотр предпочёл Gemma: в ответах Qwen встречались неверные Scratch-решения, включая ошибку на ±90, придуманное правило действий и три оборванных Python-примера. У Gemma не заметили аналогичных обрывов, но модель иногда отказывалась решить 6×7, несмотря на наличие корректного ответа, и дала два расплывчатых ответа по Scratch. В проверке также обнаружен плохой ответ на запрос о дате вне области корпуса. Полноценная человеческая педагогическая оценка ещё не проводилась; набор мал и синтетический, поэтому ни одна модель не объявляется глобально оптимальной.

До scope gate сырой поиск BGE-M3 возвращал нерелевантные материалы на всех 30 off-scope прогонах. Итоговый pipeline сначала вызывает scope classifier на Gemma 4 12B, затем выполняет retrieval только для in-scope запросов. Gate отклонил 30/30 off-scope запросов, сохранив Recall@3 100%, Recall@1 91,67%, MRR 95,56%; средняя задержка полного прохода – 307,89 мс. В отдельном маршруте с API subject `math` gate также отклонил 30/30 off-scope запросов, средняя задержка – 256,21 мс. Результаты прежних assisted tests с gold-подсказками subject/grade сюда не смешиваются. Набор мал и синтетический: gate оценивает область курса, а не фактическую правильность ответа.

Создание задания/плана сейчас разрешено только педагогу: результат получает `status: draft` и `review_required: true`. Это ограничение введено после того, как проверка выявила неправильную подсказку по делению и полный ответ внутри подсказок. Пустая выдача чата и scope gate дают детерминированный отказ; gate проверен на небольшой синтетической выборке и не гарантирует правильную классификацию произвольного текста. Локальная проверка сетевого поведения подтвердила guard от egress; физическое отключение сети не проверялось.

Последняя полная проверка: 203 теста прошли с настоящим PostgreSQL в отдельной временной БД. Сценарий на выбранной Gemma с ограничением HTTP на loopback и подтверждением прогресса также прошёл в восстановленной временной БД. Подробные результаты и известные ошибки Scratch-черновика: [итоговая проверка](LOCAL_VERIFICATION_2026_10_13.md).
