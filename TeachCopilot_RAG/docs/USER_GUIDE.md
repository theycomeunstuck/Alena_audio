# Руководство пользователя

TeachCopilot – локальное рабочее место педагога и ученика по математике и программированию (Scratch и Python). Установка, настройка моделей, импорт материалов и резервное копирование описаны в [руководстве по локальной БД и RAG](LOCAL_DATABASE_RAG.md).

## Подготовить демонстрационные аккаунты

В PowerShell откройте каталог `Alena_audio/TeachCopilot_RAG`, выполните установку и импорт каталога по локальному руководству, затем запустите:

```powershell
.\.venv-local\Scripts\python.exe scripts/seed_rich_demo.py
```

В локальной БД останутся 17 исходных профилей и добавятся 6 синтетических, всего 23. Появится отдельный аккаунт педагога `demo.rich.teacher@local.test` и шесть ученических аккаунтов:

Пароли создаются локально и сохраняются в игнорируемый файл `.local/rich-demo-credentials.json`. Откройте файл на своём ПК для входа. Не копируйте значения в документы, сообщения или репозиторий. Если файл потерян после создания аккаунтов, обратитесь к оператору БД – повторное создание вслепую не восстановит пароли.

Откройте `http://127.0.0.1:8099` и войдите по email и паролю из локального файла. Самостоятельной регистрации через интерфейс нет – аккаунты выдаёт оператор или создаёт seed-скрипт.

## Рабочее место педагога

1. В списке «Ученики» выберите карточку. На обзоре видны текущая цель, карта тем и последние наблюдения. «Ещё не наблюдали» означает недостаток данных, а не низкую способность.
2. В «Подготовить занятие» выберите тему и способ подготовки:
   - «По учебным материалам» использует только задачу по точной теме и сложности с исходным текстом, ответом и авторскими подсказками. Если подходящих задач меньше, чем запрошено, система сообщает об этом, а не создаёт дубликаты. Проверенные примеры: математика `div-408-4`, Scratch `scratch-sequence-01`, Python `python-output-01`.
   - «Новый черновик с локальной моделью» создаёт сгенерированные задания по теме. Проверьте формулировку, ответ и подсказки до использования. Это черновик, а не проверенный источник.
   В обоих режимах выберите число задач. Source-template возвращает только доступное число: для Scratch/Python – до одной задачи, для текущих математических материалов – до трёх. Учитель видит источник и ключ ответа; детский текст задачи ключ не содержит.
3. В «Наблюдение по теме» выберите тему, укажите короткий ID или название задачи, отметьте результат и вид поддержки: без подсказок, наводящий вопрос, наглядная опора или совместное решение. Запись сохраняется сразу с проверкой версии карточки. Заметка должна описывать наблюдаемое действие, а не диагноз или предположение.
4. В «Подготовить изменение профиля» введите заметку о занятии, просмотрите предложение и подтверждайте только проверенные изменения. Предложение хранит базовую ревизию. Если карточка изменилась, подтверждение остановится с конфликтом – перечитайте карточку и сформируйте новое предложение.
5. Карта отдельно показывает предварительный планировочный сигнал из старых показателей и подтверждённый вывод по наблюдениям. Для подтверждённого результата нужны две сопоставимые пары задач за последние 30 дней: независимое и поддержанное выполнение с одним task_id на пару и сопоставимой сложностью. Статус «вне ЗБР» требует неудачи в самостоятельной и совместной попытке в обеих последних парах и отсутствия успеха на любом уровне поддержки. Неудача только с наглядной опорой оставляет результат неопределённым. Полные правила приведены в [политике ЗБР](ZPD_POLICY.md).

## Рабочее место ученика

Ученик входит в отдельный аккаунт и видит только собственный профиль, доступные темы и историю без заметок педагога. В чате выберите предмет: математика, программирование, Python или Scratch. Помощник может попросить сформулировать учебный вопрос и использует ограниченный контекст предыдущего диалога. Он не меняет mastery автоматически. Если надёжный учебный источник не найден, уточните вопрос или обратитесь к педагогу; запросы вне учебных предметов, например о погоде, не обслуживаются.

## Материалы, проверка и приватность

Оператор добавляет материалы в `knowledge-data/`, указывает предмет, тему, стабильный `topic_id`, происхождение и версию источника, затем запускает импорт и переиндексацию по [локальному руководству](LOCAL_DATABASE_RAG.md). Нестандартное правило Scratch включайте в ответы только после добавления и проверки курируемого источника. Перед изменениями базы сделайте резервную копию; восстановление проверяйте только в отдельную пустую базу.

Все шесть демо-профилей синтетические. Их интересы, темп и учебные заметки придуманы для тестирования разнообразных ситуаций и не относятся к реальным детям. Класс служит контекстом, а не предписанным темпом прохождения программы. ЗБР – ограниченная педагогическая гипотеза, не диагноз и не автоматическая оценка ученика. Решения о занятии и подтверждение изменений остаются за педагогом.

## Воспроизводимая проверка

Из каталога `TeachCopilot_RAG` установите зависимости и локальный браузер Playwright, затем выполните полную проверку:

```powershell
uv pip install --python .venv-local/Scripts/python.exe -r requirements-dev-local.lock.txt
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) '.local/ms-playwright'
.venv-local/Scripts/python.exe -m playwright install chromium
.venv-local/Scripts/python.exe scripts/verify_local.py --ui
```

Проверка создаёт отдельную временную БД, запускает pytest, самопроверки политики и UI-проверку. Итог и журналы записываются в `.local/verification/latest.json` и соседние log-файлы. Команда для smoke-проверки уже запущенного интерфейса без изменения карточек:

```powershell
.venv-local/Scripts/python.exe scripts/check_ui_local.py --base-url http://127.0.0.1:8099
```

Подробная схема – в [LOCAL_SCHEMA.md](LOCAL_SCHEMA.md). Отчёт проверки показывает точный охват тестов. Метрики поиска не доказывают фактическую правильность каждого ответа модели.
