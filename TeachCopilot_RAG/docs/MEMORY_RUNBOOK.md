# Память занятий в TeachCopilot

Используются существующие PostgreSQL, аккаунты, назначения учеников и интерфейс. До содержательной проверки результатов человеком рабочий метод – `tail`. `profile_only`, `summary` и `structured` доступны преподавателю для демонстрационного сравнения. Машинный отчёт не меняет рабочий метод.

## Запуск

Команды выполняются из `Alena_audio/TeachCopilot_RAG`:

```powershell
.venv-local/Scripts/python.exe scripts/manage_local.py migrate
.venv-local/Scripts/python.exe -m uvicorn server:app --host 127.0.0.1 --port 8099
```

В отдельном терминале запустите worker. Для конечного пакета используйте `--max-jobs`; без него worker опрашивает очередь постоянно:

```powershell
.venv-local/Scripts/python.exe scripts/memory_worker.py --max-jobs 40
```

Worker и API используют одинаковые настройки `.local.env`. Авторизация и миграции не запускают генерацию автоматически. Исследовательские прогоны не следует совмещать с демонстрацией на той же локальной модели: отдельный стенд имеет собственный последовательный исполнитель.

## Преподавателю

Откройте ученика и выберите тему. Кнопка следующего шага создаёт задание; интерфейс показывает ожидание и результат. Рекомендация содержит действие, обоснование, неизвестные условия, требование просмотра и раскрываемые источники. Из неё можно перейти к существующему созданию задания. При изменении карточки или источников требуется новая рекомендация.

В разделе памяти доступны исходные наблюдения и версии контекста. Для использования в ученическом чате преподаватель подтверждает готовую версию `tail`. Подтверждение проверяет актуальность карточки и источников. Извлечённые выводы остаются черновиком до просмотра; они не записываются в компетенции автоматически.

Заметка после занятия проходит существующий просмотр предложения изменений. Вместе с ним показывается предлагаемая запись источника памяти. Подтверждение сохраняет карточку, источник и задание обновления в одной транзакции. Групповая заметка содержит явное указание, что авторство отдельных результатов не установлено.

## Ученику

Новый вопрос в интерфейсе создаёт учебную сессию. Диалог собирается сервером; переданные клиентом прошлые достижения не заменяют сохранённую историю. Повтор отправки использует тот же `client_message_id` и возвращает сохранённый ответ. При неизвестном исходе генерации интерфейс сообщает об этом; автоматического оплачиваемого повтора нет.

Завершение занятия сохраняет сессию и ставит обновление памяти в очередь. Текущий диалог и подтверждённая долговременная память используются вместе. Реплика ассистента сохраняется как часть диалога, но не становится доказательством выполненного учеником действия. Учебные сессии хранятся отдельно от сессий входа.

## API

Все операции требуют существующей серверной авторизации. ID ученика проверяется на сервере, включая доступ к заданию, версии памяти и рекомендации.

| Операция | Назначение |
| --- | --- |
| `POST /learners/{id}/next-step` | `{topic_id, method?, expected_revision?}`; ответ 202 с `job_id` |
| `GET /memory/jobs/{id}` | Устойчивый статус, результат или причина отказа |
| `GET /learners/{id}/memory?topic_id=...` | Доступные преподавателю источники и версии |
| `POST /learners/{id}/memory/versions/{version_id}/confirm` | Подтверждение версии с `expected_revision`; необязательный `interest_candidate_ids` принимает только выбранные интересы |
| `POST /task/design` | Необязательный `next_step_id`, проверка ученика, темы и ревизий |
| `POST /learners/{id}/learning-sessions` | `{topic_id, client_session_id?}` |
| `POST /learning-sessions/{id}/complete` | Завершение и задание обновления |
| `POST /v1/chat/completions` | Совместимый старый контракт; дополнительно `learning_session_id`, `client_message_id` |

Ошибки доступа дают 403/404, конфликт ревизии или повтор с другим содержимым – 409. Переполнение и ожидание очереди сообщаются явно с возможностью повторить позже. Неизвестный исход запроса сохраняется отдельно от обычного отказа.

## Проверки и ограничения

```powershell
.venv-local/Scripts/python.exe scripts/verify_memory.py
.venv-local/Scripts/python.exe scripts/verify_local.py --ui
```

Проверки создают отдельные временные локальные БД. Нагрузка использует реальную PostgreSQL, правила памяти, очередь и поиск с синтетическими векторами; модель заменена управляемой имитацией. Показатели 5/10/20 сессий не являются пропускной способностью Spiderssense. Платный проход запускается отдельно конечным скриптом `scripts/check_memory_external.py` и использует интеграционный журнал бюджета.

Локальная проверка полного входа учитывает сообщения и схему, но использует эвристику `cl100k_base` с запасом. Это другой токенизатор, поэтому отсутствие скрытого усечения внутри Ollama полностью не доказано. Отказ и доступные сырые результаты сохраняются. Исследовательский стенд учитывает такой случай как ошибку метода. В приложении последняя готовая память остаётся доступной с отметкой актуальности.

Внешние ответы по умолчанию выключены. Их проекция, локальная проверка свободного текста, журнал резервов и настройка описаны в [EXTERNAL_ANSWERS.md](EXTERNAL_ANSWERS.md). Исходные карточки и необработанные заметки целиком во внешний запрос не входят. Проверки приватности на синтетических данных не доказывают полную анонимность произвольного свободного текста.
