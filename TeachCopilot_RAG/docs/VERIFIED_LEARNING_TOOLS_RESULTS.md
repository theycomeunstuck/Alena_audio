# Проверяемые учебные операции: вычисления готовы, перенос распознавания не подтверждён

18 октября 2026. Данные синтетические, рубрика и содержательные оценки человеком не проверены. Этот этап приложения отделён от замороженного исследования четырёх методов памяти.

Реализованы локальные проверяемые операции для деления, разрядов частного, нового упражнения с внутренним нулём и точного вывода литерального `print`. Программные проверки проходят. Однако оба живых пакета не вызвали инструменты ни разу: словарная маршрутизация оказалась слишком узкой. Называть эту версию общим улучшением точности учебного чата нельзя. Обычная генерация продолжает ошибаться в свойствах предлагаемых упражнений.

## Что сохранено в приложении

`learning_math.py` вычисляет частное, остаток, обратную проверку и разряды, включая нулевые. Новый пример подбирается по проверяемому свойству; частное не попадает ни в текст задания, ни в его метаданные. Уже видимые примеры исключаются в пределах ограниченного текущего диалога. Это не свидетельство выполнения учеником.

`learning_python.py` разбирает AST как данные: разрешены только прямые вызовы `print` с константами и строковыми `sep`/`end`. Переменные, выражения, импорты, файлы, `eval` и `exec` не исполняются. Ограничены исходник, число вызовов, аргументов и объём вывода; некорректные Unicode-суррогаты отклоняются без замены. Пробелы, внутренние кавычки и окончание строки сохраняются.

Ветка вызывается после существующей проверки учебной области и указателя на прежний вопрос ученика. Операнды и код берутся из текущей реплики. Неизвестные дополнительные условия, составное выражение и просьба только о подсказке передаются обычному чату. Проверенный ответ имеет `learning_tool` с областью проверки, пустые `sources`/`citations` и `student_competence_assessed=false`. Он не изменяет подтверждённые компетенции.

Примеры поддержанного регрессионного языка: «Проверь 3663 : 11 = 333», «Поясни разряды частного 4928 : 16 = 308», «Что выведет этот код?» с отдельным безопасным блоком `print`. Их работа проверена на границах RAG/HTTP/API с управляемыми ответами классификатора. Это не результат отдельного живого прогона этих реплик. Классификатор всё ещё требует модельного вызова; нулевые токены детерминированного ответа исключают его стоимость.

Все ответы создала модель, поэтому механические гарантии вычислителей к ним неприменимы. После результата словарь по этим восьми не расширялся. В наборе нет отрицательных случаев; он не оценивает ложные срабатывания на произвольной речи.

## Смысловой просмотр

Все 24 исходных исхода и восемь новых ответов рассмотрены отдельным AI-рецензентом. Это некалиброванная вспомогательная оценка, `human_reviewed=false`; она не заменяет проваленный gate формального судьи исследования памяти.

В исходных 24 случаях отмечены четыре существенные проблемы: VT01 неверно называет множители обратной проверки; VT03 ошибочно объясняет нулевой разряд; VT05 и VT06 предлагают упражнения без требуемого свойства. VT20 неоднозначен, отдельно отнесён к `uncertain`; VT11 не оценён по содержанию из-за отсутствия ответа. Полезность: 15 полезных, пять частично полезных, три неполезных, один не оценён. Два несоответствующих упражнения не означают, что все 23 технических ответа неверны.

В новых восьми ответах шесть признаны полезными, два нарушают условие: VTS05 предлагает `304 : 2 = 152`, где в частном нет внутреннего нуля; VTS06 предлагает `420 : 4`, хотя запрошен двузначный делитель. VTS07 содержит корректно экранированные кавычки в фактическом `public`; ошибки JSON или Python в этом случае нет. По одному корректному ответу не устанавливается освоение ученика.

Причина остаётся разделённой: вычислители работают в своём контракте; новые формулировки не допускает программный селектор; затем обычная модель генерирует неподходящий пример. Память не записывалась и не извлекалась этим стендом; приписывать эти ошибки долговременной памяти нельзя.

## Приёмка и запуск

После v1.1 прошли 627 тестов без пропусков, включая восемь браузерных проверок, и 52 проверки правил данных. Проверены ограничения вычислений/AST, защита от составных выражений и неизвестных условий, запрет раскрытия ответа при подсказке, корректность старого указателя, авторизация, серверная история и повтор сообщения без нового источника или модельного запроса. Это программные гарантии; они не отменяют отрицательного результата новых формулировок.

Машиночитаемая [сводка проверки](VERIFIED_LEARNING_TOOLS_VERIFICATION.json) фиксирует отдельные результаты пакетов, AI-просмотра, тестов и готовности.

API и worker перезапущены при пустой очереди. `http://127.0.0.1:8099/ready` подтверждает PostgreSQL, schema 11, индекс и локальные модели. Рабочая память остаётся `tail`; преподавательский просмотр интересов и компетенций сохраняется.

Коммиты для отката: `7b8c3a7` – вычислители и первый протокол; `c1cd84a` – одна коррекция распознавания, replay и новый набор. Итоговые материалы сохраняются отдельным следующим коммитом. Не следует сбрасывать всю ветку с посторонними изменениями; нужную правку можно отменять отдельным `git revert` после проверки состава коммита.

Команды из `TeachCopilot_RAG` (каждый выводной каталог должен быть новым):

```powershell

.venv-local/Scripts/python.exe scripts/replay_verified_tool_selection.py --input-dir .local/verified_learning_tools_v1/run01 --output-dir .local/verified_learning_tools_v1/replay-new

```

Повтор последней команды после просмотра результатов не создаёт новый отложенный набор. Исходный runner v1 и исправленный v1.1 сохранены по своим Git-коммитам и в архиве.

Материалы: `.local/verified_learning_tools_v1/{run01,replay01,smoke01,review01,smoke_review01,receipts}`. Архив внешнего проекта – `nirs/artifacts/verified_learning_tools_v1_20261018.zip`, с исходниками двух версий и SHA256 каждого файла. Итоговая отметка обработки содержит хеш архива.

Снимки исходников берутся из Git с его каноническими переводами строк. SHA256 фактически использованных Windows-файлов сохраняются отдельно в `preregistered.json` и отчётах целостности; побайтовое совпадение Git-снимка с рабочим файлом при CRLF/LF не предполагается.

Требуется новый протокол и новый набор: улучшение на старых 24 при нуле из восьми новых уже показывает риск подгонки. Этот этап завершён как отрицательная проверка текущей маршрутизации, а не как доказанное исправление всех учебных ошибок.
