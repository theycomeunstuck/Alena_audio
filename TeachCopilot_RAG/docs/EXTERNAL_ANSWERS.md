# Локальные вычисления и внешний ответ

По умолчанию TeachCopilot отвечает локально. `local_app.answer_adapter.AnswerAdapter` подключается только к последней генерации в `RagService.answer`. Проверка предметной области, разрешение ссылок в вопросе, PostgreSQL, поиск, embeddings и обновление памяти продолжают использовать локальные компоненты. Адаптер также поддерживает назначение `next_step`; текущий worker рекомендации использует локальную модель.

## Путь запроса

1. Сервер проверяет доступ к ученику и собирает известные идентификаторы. Передача полного контекста идентификации подтверждается аргументом `identity_context_complete=True`. При его отсутствии используется локальная генерация.
2. Создаётся `EducationalProjection`: тема, текущая реплика, полный переданный диалог и разрешённые выдержки памяти и учебных материалов. В памяти разрешены только `source_id`, `claim` и `quote`; в материале – `source_id`, `title`, `content`. Для чата сервер должен передавать только подтверждённую долговременную память. Версия `educational-projection-v2` добавляет `interests` и `avoided_interests`: до восьми коротких названий по 120 символов. Оба поля проверяются в фактически отправляемом запросе; полная карточка и личные рассказы в них не входят. Короткая социальная ветка чата остаётся локальной.
3. Адаптер проверяет соответствие текущей реплики и диалога реальному локальному запросу. Полная карточка, исходный системный промпт, журнал, заметки преподавателя, пути файлов и снимки записей в проекцию не входят. Передача закрытых ответов преподавателю оставляет генерацию локальной.
4. Известные имена и идентификаторы удаляются локально, включая части полного имени. Источники получают временные псевдонимы `S1`, `S2`; такие же замены выполняются в схеме ответа. Исходные идентификаторы возвращаются в полях ответа после получения результата.
5. Проверяются все строки отправляемых сообщений и схема ответа, включая текущую реплику, прошлые реплики и цитаты. Контакты, ссылки, длинные числовые идентификаторы, пути, невидимые символы и некоторые признаки личных данных запрещают внешнюю отправку.
6. Локальная модель отдельно проверяет подготовленный запрос на персональные или неоднозначные сведения. Нужен строго заданный ответ `safe_to_send=true, uncertain=false`. Ошибка, неполный JSON или неопределённость направляют исходный запрос локальному генератору.
7. Внешний вызов выполняет существующий `research_memory.spiderssense.SpiderssenseClient` с устойчивым журналом резервов. Ошибка уже начатого вызова передаётся вызывающей стороне; повторная генерация и автоматический локальный дубль не запускаются.

`answer_routing` содержит выбранный backend, код причины и версию политики. Диагностика маршрутизации не сохраняет текст приватного запроса. Внешние usage/metadata возвращаются отдельно для учёта времени, токенов и стоимости.

## Включение

Укажите явный путь в `TEACHCOPILOT_EXTERNAL_ANSWERS_CONFIG`. Без переменной клиент провайдера не создаётся. Файл имеет следующий вид:

```json
{
  "kind": "local_app_external_answers_v1",
  "enabled": false,
  "spiderssense": {
    "model": "<явно выбранная модель>",
    "pricing_verified": true,
    "pricing_source": "https://spiderssense.com/v1/models",
    "input_usd_per_million": "<проверенный тариф>",
    "output_usd_per_million": "<проверенный тариф>",
    "ledger_path": ".local/research_memory/spiderssense_integration_budget.sqlite3",
    "max_cost_usd": "0.40",
    "max_calls": 20,
    "max_output_tokens": 1536,
    "key_file": ".local/research_memory/spiderssense.key",
    "use_json_schema": false,
    "use_json_object": true
  }
}
```

Перед включением требуется заполнить проверенные тарифы провайдера и выполнить общий переход бюджета исследования. Этот пример выключен и содержит незаполненные значения. Создание нового журнала не обнуляет расходы и неизвестные резервы предыдущих этапов. Допустимы максимум $0.40 и 20 интеграционных вызовов; более крупные лимиты отклоняются до создания клиента. Учёт Spiderssense сохраняет неизвестный исход как резерв, запрещает смену настроек существующего журнала и не повторяет запросы автоматически. Ключ читается только непосредственно перед вызовом.

При настроенной PostgreSQL каждый фактический модельный вызов проходит через общий диспетчер `GenerationScheduler`: один локальный вызов и до четырёх внешних вызовов одновременно во всех процессах API и worker. Общий предел 40 ожиданий учитывает очередь `memory_jobs` и ожидающие вызовы в `generation_admission`; интерактивная генерация имеет приоритет перед фоновым писателем. Переполнение и истечение ожидания дают явный отказ до отправки запроса. Локальный семафор дополнительно ограничивает внешние вызовы одного процесса четырьмя; пятый получает `AnswerCapacityError`. Для этой схемы нужна миграция 011.

Активный вызов удерживает сессионную advisory-блокировку PostgreSQL, поэтому истечение записи само по себе не допускает параллельную генерацию. После исчезновения соединения или исключения во время вызова сохраняется консервативный резерв `unknown_outcome` до истечения тайм-аута запроса плюс 30 секунд. Неактивные ожидания протухают через 30 секунд. Недоступная PostgreSQL запрещает новый внешний вызов. Запрос не повторяется автоматически после неизвестного исхода. Подменённые тестовые runtimes без настроенной БД используют только локальный семафор.

## Проверка и ограничения

```powershell
.venv-local/Scripts/python.exe -m pytest tests/test_answer_adapter.py tests/test_local_rag.py -q
```

Тесты используют только синтетические данные и подменённый HTTP-транспорт реального клиента Spiderssense. Проверяется фактически передаваемый `Request.data`, включая текущую реплику, цитаты и схему, отсутствие исходных карточек/заметок, локальная обработка неопределённости и сохранение резерва без повторного вызова при неизвестном сетевом исходе. Платные вызовы в этих тестах отсутствуют.

Это консервативный шлюз с локальной проверкой, а не доказательство полной анонимности свободного текста. Неизвестные имена, склонения, косвенные идентификаторы, необычные способы кодирования и ошибки локальной модели могут быть распознаны неполно. Для реальных данных выбор внешнего режима требует отдельной оценки этой границы; локальный режим доступен без внешнего провайдера. Слишком длинные выдержки не обрезаются скрыто: они оставляют ответ локальным. Проверка конфиденциальности выполняет дополнительную локальную генерацию, поэтому её время следует учитывать отдельно от времени внешнего ответа.
