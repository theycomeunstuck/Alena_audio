## Зафиксированные требования пользователя

1. Сохранять полную историю взаимодействия, сообщения ребёнка и помощника, точное время и происхождение сведений. Исправления добавляются отдельными записями.
2. Считать одним сеансом все разговоры ребёнка за календарный день. Внутри дня объединяются разные темы и технические сессии. Семь последних сеансов означают семь последних активных дней, которые могут охватывать несколько месяцев.
3. Поддерживать три уровня контекста – последние 20 отдельных сообщений, дневную сводку и сводку семи последних активных дней. Исходный архив остаётся доступным целиком.
4. Передавать сводки в системный промпт. В отображаемом времени сводок использовать дату и максимум час. Состав и порядок префикса должны быть детерминированными. Новые сведения обновляют сводку сразу по изменению входа.
5. Хранить UTC-момент события, IANA-зону записи и устойчивую календарную принадлежность. Учебный пояс по умолчанию – `Asia/Tomsk`. Пользовательский пояс отображения настраивается отдельно. Для существующих записей календарная группировка по Томску считается восстановленной по умолчанию, исходная зона события может оставаться неизвестной.
6. Пассивно собирать сведения из обычного разговора. Активно предлагать короткий добровольный вопрос в подходящий момент, с возможностью пропуска. Выбрана начальная реализация с одним предложением за активный календарный день.
7. Для старого события искать по всей собственной переписке ребёнка. Каталог должен учитывать общие темы и время.
8. Делить диалог на фиксированные фрагменты с перекрытием. Для длинного абзаца перекрытие увеличивается. Пользователь исключил смысловое разбиение по результатам прежней проверки.
9. Хранить одно актуальное состояние классификатора и его меток. Переклассификация атомарно заменяет производные данные. Исходные сообщения сохраняются полностью.

## Доступ и модельный контекст

Автоматическая память собственной переписки ограничивается парой `learner_id` и авторизованный `actor_id`. Детские реплики обозначаются `self_report`, связанные ответы помощника – `context_only`. Собственный текст ребёнка сохраняется и после ошибки генерации. Ответ помощника включается по проверенной сохранённой связи. Преподавательские приватные источники и переписка другого участника исключаются.

Подтверждённые наблюдения используют существующий механизм teacher review и grant. Автоматическое накопление переписки не повышает статус исходных реплик и не подтверждает компетенции или устойчивые интересы. Новый ребёнок должен получать собственный разговорный контекст сразу. Явно выбранный поиск по подтверждённым наблюдениям продолжает проверять соответствующее разрешение.

В SYSTEM передаются стабильные сводки, затем контекст текущего поиска. Последние 20 отдельных сообщений передаются обычными ролями. Текущий вопрос включается один раз. Ограничение объёма применяется к полному промпту, пропуск целого сообщения или дня отражается в диагностике. Архивная пагинация сохраняет доступ ко всей истории.

## Реализованная поверхность API

Следующие маршруты подключены к серверным контрактам и покрыты целевыми тестами. Основная цепочка сохранения, сводок, поиска и ответа также проверена с настоящими локальными сервисами. Перед новым изменением сверить сигнатуры в коде.

| Маршрут | Назначение |
|---|---|
| `GET /auth/me` | `profile.display_timezone` и доступность функций |
| `PATCH /auth/preferences` | Сохранить проверенный IANA `display_timezone` |
| `GET /learners/{id}/conversation-memory` | Ответ `{learner_id, hierarchy}` с собственной памятью текущего авторизованного участника |
| `GET /learners/{id}/conversation-history` | Полная собственная история с пагинацией `limit` до 100 и `before_source_order`. Ответ содержит `messages` и `next_before_source_order` |
| `GET /learners/{id}/conversation-catalog` | Ответ `{learner_id, catalog}` с актуальными метками и временными фасетами собственной переписки |
| `POST /learners/{id}/conversation-catalog/reclassify` | Пересобрать каталог собственной переписки выбранным сервером классификатором и атомарно заменить актуальное состояние |
| `GET /learners/{id}/checkin` | Ответ `{checkin}` с дневным предложением, в том числе перед первым сообщением. Допустим `learning_session_id` |
| `POST /learners/{id}/checkin/{checkin_id}/shown` | Зарегистрировать фактический показ вопроса. Ответ `{checkin}`, тело может содержать `learning_session_id` |
| `POST /learners/{id}/checkin/{checkin_id}/skip` | Сохранить добровольный пропуск. Ответ `{checkin}` |
| `POST /v1/chat/completions` | Сохранить текущую реплику, связать `metadata.checkin_id`, собрать серверную память и выполнить ответ |

Сводки учителя со старыми полями `last_session` и `last_seven_sessions` сохраняют прежний смысл. Новая календарная память показывается ученику в собственной области. Endpoint собственной переписки всегда привязан к текущему авторизованному участнику, включая запрос преподавателя.

Для прямого запроса старого API без `learning_session_id` подключён `ensure_conversation_session` по участнику и теме. Сервер сохраняет принятую последнюю реплику и сгенерированный ответ через обычный журнал, возвращает идентификаторы для продолжения и повторов. Подлинность исторических ответов помощника, присланных клиентом в `messages`, отдельно не устанавливается. Их нельзя сохранять как новые серверные ответы. Сохранение прямого запроса проверено в живом сценарии нового ученика.

`conversation_context` и callback архивного поиска создаёт сервер для локального `RagService`. Доступность новой функции проверяется по возможностям store. Старые внедрённые тестовые настройки без `personal_memory_enabled` получают выключенный feature flag, а настоящая конфигурация `Settings` сохраняет включённое значение по умолчанию. Это изменение входит в исправление совместимости UI-тестов.
