# Что проверить на сервере перед использованием

Эта ветка собрана и проверена на машине без GPU, без PostgreSQL и без
установленных зависимостей сервиса. Всё, что можно было проверить в таких
условиях, проверено (137 тестов pytest, 52 теста learner-data, прогоны на живой
облачной модели). Но три вещи проверить было негде — их нужно пройти на сервере
до того, как этим начнут пользоваться на занятиях.

Порядок важен: каждый следующий пункт опирается на предыдущий.

---

## 1. Зависимости и импорт (5 минут)

```bash
cd TeachCopilot_RAG
pip install -r requirements.txt
python -c "import fastapi, requests, psycopg2, sentence_transformers; print('ok')"
```

**Что проверяем:** в разработке эти пакеты не были установлены, весь новый код
писался так, чтобы работать и без них (тяжёлые импорты ленивые). На сервере,
где они есть, ничего не должно сломаться от того, что они появились.

**Признак проблемы:** ImportError при запуске любой команды из
[HOWTO.md](HOWTO.md).

## 2. Тесты целиком (2 минуты)

```bash
cd TeachCopilot_RAG
pytest tests/ -q
cd .. && python learner-data/tools/validate.py --strict
python learner-data/tools/selftest.py
```

**Что проверяем:** два файла тестов — `test_server_contract.py` и
`test_json_rag.py` — требуют `fastapi` и sentence-transformers, поэтому в
разработке не запускались ни разу. Здесь они запустятся впервые.

**Ожидаемо:** все тесты зелёные. Если падает `test_server_contract.py` —
смотрите пункт 3, скорее всего дело в новых эндпоинтах.

## 3. Сервер и два новых эндпоинта (10 минут)

```bash
cd TeachCopilot_RAG
uvicorn server:app --host 0.0.0.0 --port 8099
```

В другом терминале:

```bash
curl -s localhost:8099/health

curl -s -X POST localhost:8099/task/design \
  -H "Content-Type: application/json" \
  -d '{"learner_id":"zvezdin-artem","count":3}' | head -40

curl -s -X POST localhost:8099/learner/update \
  -H "Content-Type: application/json" \
  -d '{"learner_ids":["zvezdin-artem"],"notes":"Луч начертил после наводящего вопроса.","apply":false}'
```

**Что проверяем:** оба эндпоинта написаны, но **ни разу не запускались** — только
прочитаны и скомпилированы. Возможные проблемы: несовпадение типов в моделях
pydantic, порядок импортов в `server.py`, таймауты.

**Ожидаемо:**
- `/task/design` возвращает `card`, `text_for_child`, `text_for_tutor`;
- `/learner/update` с `apply: false` возвращает диффы и **ничего не пишет** на диск;
- контракты описаны в [CONTRACTS.md](CONTRACTS.md).

**Важно:** `/learner/update` с `apply: true` изменяет файлы карточек. Первый раз
запускайте только с `apply: false`.

## 4. Локальная модель вместо облачной (30 минут)

```bash
# .env
AI_PROVIDER=lmstudio
TEACHCOPILOT_CHAT_MODEL=<ваша модель>
```

```bash
cd TeachCopilot_RAG
python scripts/check_llm_contract.py --runs 10
```

**Что проверяем:** промпты отлаживались на DeepSeek V3 — большой облачной
модели. Локальная 4B будет ошибаться заметно чаще. Скрипт покажет долю чистых
прогонов и что именно модель нарушает.

**Ориентир:** на DeepSeek получилось 16/16 (100%). На локальной модели ждите
меньше. Если ниже 70% — сначала правьте
`prompts/task_designer_prompt.txt` (пример готовой карточки в нём — главный
рычаг для слабых моделей), и только потом меняйте модель.

**Обязательно проверьте окно контекста:** нужно минимум 8192. При типовых 4096
групповое обновление обрежется посередине и вернёт неполный JSON **без всякой
ошибки**. Замеры: карточка-задание ~2 400 токенов, разбор заметок на 5 учеников
~2 000 токенов.

**Думающие модели** (qwen3 и подобные) отвечают медленно и иногда оставляют
`content` пустым. Код умеет вытащить ответ из `reasoning_content`, но для
группового прогона лучше отключить размышление (`/no_think`).

## 5. pgvector, если он используется (20 минут)

```bash
python scripts/apply_schema.py
python scripts/ingest.py --dir data
python -c "from pipeline.retrieval import retrieve_material; \
    print(retrieve_material('луч и отрезок', topic_id='math.g3.geometry.point_line_ray_segment', grade='3')[0].origin)"
```

**Что проверяем:** поиск материала устроен как цепочка из трёх уровней —
pgvector, локальный JSON-индекс, лексический поиск на stdlib. В разработке
работал только третий. На сервере с базой должен включиться первый.

**Признак успеха:** `origin` в выводе равен `pgvector`, а не `lexical`.
Если `lexical` — база не подхватилась, смотрите логи с
`TEACHCOPILOT_DEBUG_RAG=1`.

## 6. Полный сценарий одного урока (15 минут)

```bash
cd TeachCopilot_RAG

# до урока
python ../learner-data/tools/zpd.py zvezdin-artem

# карточки на группу, на печать
python scripts/make_task_card.py --group detektivy-3 --format html --out /tmp/cards.html

# после урока: сначала предпросмотр, файлы не меняются
python scripts/update_learner_card.py --group detektivy-3 --notes-file lesson.txt

# и только потом запись
python scripts/update_learner_card.py --group detektivy-3 --notes-file lesson.txt --apply

# отчёт
python ../learner-data/tools/progress_report.py zvezdin-artem
```

**Что проверяем:** что всё вместе работает на реальном железе и реальной
модели. Отдельно посмотрите на печатную форму: открывается ли в браузере,
нормально ли встаёт на A4, не разъезжается ли кириллица.

## Что заведомо не проверено и требует внимания

1. **Педагогическая корректность заданий.** Код проверяет арифметику в тексте
   (равенства сходятся) и то, что сюжет опирается на интересы ребёнка. Он не
   проверяет, осмысленно ли условие и по теме ли задача. **Карточку нужно
   прочитать перед выдачей ребёнку** — лист для взрослого печатается с ответами
   именно для этого.

2. **Пороги правила ЗБР** (0.85 / 0.30, alpha 0.4) — обоснованное предложение, а
   не измеренная на детях величина. Проверьте на нескольких реальных занятиях,
   что переход темы в «делает сам» совпадает с ощущением репетитора.

3. **Персональные данные.** Все 17 учеников в репозитории вымышленные.
   Реальные ФИО, контакты и записи занятий в публичный репозиторий класть
   нельзя. Отдельно: облачный провайдер (DeepSeek и любой другой) — это
   передача данных третьей стороне; для реальных детей это отдельное решение,
   которое стоит принять до первого запуска, а не после.

4. **Старый `pipeline/profile_agent.py`** пишет в PostgreSQL собственные оценки
   0–100 по своим порогам. Это второй, конкурирующий с ЗБР источник правды об
   освоении. Пока живы обе ветки, данные о ребёнке будут расходиться. Решение
   не принято — см. [HANDOFF.md](../../HANDOFF.md), раздел 4.
