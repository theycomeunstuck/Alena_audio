# Разговор, интересы и следующие сессии

Реализовано 18 октября 2026. Это расширение приложения, отдельно от замороженного сравнения четырёх способов учебной памяти.

Последующая проверка: [20 последовательных сессий](CONVERSATION_LONGITUDINAL_RESULTS.md). Она показала перенос интересов, лишние кандидаты и ошибки учебных объяснений; 66 HTTP 200 из 80 не являются оценкой правильности. После ограниченного исправления маршрутизации пройдены 384 теста приложения и 52 проверки карточки. Первоначальные пилоты ниже сохранены отдельно.

## Как это работает для ребёнка

Короткий рассказ о своём дне, интересе, приветствие или благодарность могут получить короткий локальный ответ. Такой ответ не требует учебных материалов и не получает выдуманных цитат. Учебный вопрос со вставкой об увлечении продолжает учебную ветку. После короткого отступления помощник может вернуться к реальному предыдущему вопросу ученика; реплики ассистента не используются как источник исходной задачи.

Чат обращается к ребёнку. Известные интересы используются уместно, без обязательного игрового сюжета в каждом ответе. Текущая просьба и запрет сюжета имеют приоритет. Короткая беседа остаётся локальной даже при включённом внешнем адаптере. Неподдерживаемые справочные запросы получают перенаправление к учебной теме.

## Как интерес становится долговременной памятью

1. Ученик начинает учебную сессию и пишет сообщения. Сервер сохраняет исходные реплики с автором. Повтор сообщения возвращает прежний ответ.
2. Завершение сессии ставит существующее фоновое обновление памяти. Для завершённого диалога отдельный локальный вызов предлагает предпочтения только из реплик ученика.
3. У каждого предложения есть `candidate_id`, `operation`, `interest`, `source_id` и буквальная `quote`. ID, авторство и буквальность проверяются программно. Правильность толкования цитаты требует просмотра.
4. Преподаватель открывает ученика, выбирает тему и обновляет историю памяти. В черновике видны интересы, цитаты и источники. Все флажки изначально сняты.
5. Кнопка «Подтвердить память для помощника» атомарно принимает учебную память и только выбранные предпочтения. Карточка, ревизия и запись просмотра сохраняются в одной транзакции.
6. Подтверждённые интересы находятся в общей карточке и доступны чату и подбору задания по другой теме. Учебные источники разных тем при этом остаются раздельными. Подтверждённая компетенция из интереса не создаётся.

| Операция | Значение |
|---|---|
| `add` | Добавить явно выраженный интерес. Само по себе не снимает запрет сюжетов. |
| `remove` | Убрать интерес и исключить соответствующий сюжет из подсказок. |
| `avoid` | Не предлагать этот сюжет, сохранив сам интерес в карточке. |
| `allow` | Снять ранее записанный запрет этого сюжета. Само по себе не добавляет интерес. |

Пример: «Мне нравится Minecraft, но задачи про него не хочу» может дать два предложения: `add` и `avoid`. После выбора обоих игра остаётся интересом ребёнка, но не предлагается как сюжет задания. «Вчера впервые поиграл, пока не знаю, понравилось ли» не является основанием постоянного предпочтения.

## Контракт подтверждения

Прежний endpoint расширен необязательным полем:

```json
{
  "expected_revision": 3,
  "interest_candidate_ids": ["interest-<идентификатор из черновика>"]
}
```

Запрос: `POST /learners/{id}/memory/versions/{version_id}/confirm`. Отсутствующее поле и пустой массив подтверждают только учебную память. После подтверждения версии изменить выбор этим endpoint нельзя. Повтор с тем же выбором идемпотентен; другой выбор возвращает `409`. Конфликт карточки или источников отклоняет всю транзакцию. Чужие источники и неверные цитаты отклоняются. Принятый выбор, автор просмотра и ревизия сохраняются в `context.interest_review`, исходные предложения остаются в истории.

`GET /learners/{id}/memory` показывает `versions[].context.interest_candidates` и `interest_extraction`. Ошибка извлечения интересов не уничтожает готовую учебную память: преподаватель видит понятную отметку, техническая диагностика и сырой ответ остаются в задании. Автоматической повторной генерации нет.

## Приватность и пределы

Внешняя проекция версии `educational-projection-v2` дополнена только короткими `interests` и `avoided_interests`: до восьми значений по 120 символов. Полная карточка и происхождение интересов в эти поля не входят. Они проходят те же локальные удаления идентификаторов и проверку фактически отправляемого запроса, что текущая реплика и цитаты. Неопределённость оставляет ответ локальным.

Память интересов не равна памяти всех событий жизни. Разовый рассказ может получить отклик, не превращаясь в постоянный профиль. Синонимы интересов автоматически не объединяются. Ранее существовавшая схема карточки допускает до трёх строк `rag_context.avoid`, включая учебные ограничения. Переполнение явно отклоняется; старые ограничения не вытесняются. `allow` снимает только запреты со строгим префиксом «Не использовать сюжет: ».

Разрешение возврата видит до восьми прошлых реплик ученика, суммарно до 4800 символов. Социальная ветка ограничена короткими репликами до 800 символов и ответом до 192 токенов. Это не неограниченный разговорный агент. Проверка большого входа извлечения учитывает схему, но использует эвристику токенизации; скрытое усечение внутри Ollama полностью не исключено.

Старая версия API без учебной сессии продолжает работать, но такие сообщения не создают долговременные источники. Для переноса интересов нужны создание и завершение сессии, работающий worker и явный выбор преподавателя.

## Проверка и воспроизведение

Приложение использует прежнюю схему БД версии 11, дополнительных миграций нет. Команды выполняются из `TeachCopilot_RAG`:

```powershell
.venv-local/Scripts/python.exe scripts/verify_local.py --ui
.venv-local/Scripts/python.exe scripts/memory_worker.py
```

Конечные локальные пилоты запускаются отдельно. Для каждого нового запуска нужен новый каталог; существующие результаты не перезаписываются:

```powershell
.venv-local/Scripts/python.exe scripts/check_conversation_interests.py --output-dir .local/conversation_memory_v1/new-interests-run
.venv-local/Scripts/python.exe scripts/check_conversation_dialogue.py --output-dir .local/conversation_memory_v1/new-dialogue-run
```

Первый выполняет восемь извлечений, второй – три разговора с локальным поиском. Внешний провайдер не вызывается. Ожидания и параметры записываются до генерации, затем сохраняются исходные ответы. Пилоты используют синтетические данные, содержательно не проверенные человеком.

Проверено: 379 тестов приложения без пропусков, включая восемь браузерных проверок, и 52 проверки правил карточки. Реальный локальный пилот извлечения: 8/8 технически приняты, все восемь соответствуют заранее записанным ожиданиям по экспертному просмотру ассистента. Три разговора сформировали ответы; в одном учебный ответ излишне многословен. Это ограниченная проверка, не доказательство образовательного эффекта или качества произвольного общения.

Артефакты находятся в `.local/conversation_memory_v1/`: `verification/`, `interests_pilot/`, `dialogue_pilot/`, `chat_pilot/`. В `chat_pilot/` сохранены также пять невалидных запусков через ASCII pipe и первоначальный результат 4/5 корректного UTF-8 пакета. Противоречие флагов смешанной реплики исправлено явным приоритетом учебного запроса и проверено offline replay; исходный результат не переписан.
